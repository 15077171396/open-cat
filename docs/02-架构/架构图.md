- **上传不走 COS 直传**：三端 multipart 交给后端，由后端做魔数/类型校验与 PNG→WebP 转码后转存。

- 管理端路由权限为**显式规则表且 fail-closed**：`(method, path 正则) → 权限码`，未登记的管理路由一律 403。

## 三、定时任务协作机制

scheduler 是独立容器（`python -m scheduler.tasks`），与主应用通过「MySQL 配置表 + Redis 双通道」解耦：管理面写期望状态，执行面热重载并对齐。

```mermaid
sequenceDiagram
    autonumber
    actor PG as 管理端「定时任务」页
    participant API as 管理端 API
    participant CFG as scheduled_job_configs<br/>（MySQL）
    participant SCH as scheduler<br/>（APScheduler）
    participant R as Redis ops:*
    participant JOB as 任务 handler

    PG->>API: 启停 / 改周期
    API->>CFG: 写期望状态
    PG->>API: 立即执行（需 scheduler:manage 权限）
    API->>R: LPUSH ops:jobs:commands
    SCH->>CFG: 每 5 秒比对配置指纹
    SCH->>SCH: 指纹变化才 add/remove（热重载，不重复 add_job）
    SCH->>R: 写 ops:jobs:applied（生效配置 + 存活心跳，TTL 120s）
    PG->>R: 读心跳 → 状态 ok / failed / stale / never / disabled
    SCH->>JOB: 定时触发 或 LPOP 命令立即执行
    JOB->>R: record_job_run 心跳（单任务 TTL 3 天）
    PG->>PG: 展示「保存≠生效（待生效）」
```

防护设计：进程内闩锁挡「调度触发 vs 手动触发」并发；daily 任务显式 `Asia/Shanghai` 时区；`misfire_grace_time` 区分 interval / daily 两档。

注册任务清单（任务体固定在代码 `JOB_FUNCS`，后台只能启停与改周期，不能增删）：

| job_id | 默认周期 | 作用 |
|---|---|---|
| `flush_view_counts` | 每 1 分钟 | Redis 浏览量增量合并落库（写放大降为 1/60） |
| `check_vip_expiry` | 每日 02:00 | VIP 过期批量降级 |
| `push_new_urls_to_baidu` | 每日 03:00 | 推送近 26h 新/改 URL（每类设上限） |
| `push_new_urls_to_indexnow` | 每日 03:10 | Bing IndexNow 推送 |
| `cleanup_audit_logs` | 每日 04:00 | 审计日志按保留期清理 |
| `cleanup_search_logs` | 每日 04:30 | 搜索日志清理 |
| `cleanup_content_views` | 每日 04:40 | 浏览归因清理 |
| `data_quality_check` | 每日 05:00 | 只读数据质量巡检，结果写 Redis 供状态卡展示 |

## 四、三端会话与鉴权

| 端 | access token | refresh token | 401 处理 | 登录方式 |
|---|---|---|---|---|
| 用户端 Web | httpOnly Cookie（JS 不持有） | httpOnly Cookie | 共享同一刷新请求 + 重放一次；认证端点豁免；重放仍 401 清态 | 账号密码 / 短信验证码，TOTP 可选 |
| 管理端 Web | sessionStorage + Bearer 头 | httpOnly Cookie（刻意不落 storage） | 同上；彻底失败整页回登录页 | 同上 + 强制 admin 角色 |
| 小程序 | wx storage + Bearer 头 | wx storage，续期放请求体 | 刷新 → 重放 → 微信静默重登 → 清态 | `wx.login` 静默登录 + 账号绑定 |

三端到达后端后走同一条鉴权链：

```mermaid
flowchart LR
    REQ["请求到达"] --> PICK["取凭据<br/>Bearer 优先 · 回退 httpOnly Cookie"]
    PICK --> VER["JWT 签名与类型校验"]
    VER --> REV{"jti 黑名单 / token 版本？"}
    REV -->|"已吊销"| DENY["401"]
    REV -->|"有效"| LOAD["加载未软删除用户"]
    LOAD --> PERM{"管理端路由？"}
    PERM -->|"是"| RBAC["权限码规则表匹配<br/>fail-closed：未登记一律 403"]
    RBAC --> AUD["敏感动作审计同事务落库"]
    PERM -->|"否"| OK["进入业务"]
    RBAC --> OK
```

令牌吊销采用**双失效**：Redis `jti` 黑名单 + 用户级 token 版本号，改密码 / 登出即时全端失效。

## 五、请求分流与预渲染降级

真实用户走 nginx 静态产物；爬虫由 UA map 分流到预渲染服务，**任何情况下都不让爬虫拿到 5xx**。

```mermaid
flowchart TB
    B["爬虫请求（UA 命中 nginx map）"] --> N["307 内部跳转 @prerender"]
    N --> W{"路径在路由白名单？"}
    W -->|"否（未收录路由）"| R404["真 404"]
    W -->|"是"| M{"Redis 缓存命中？"}
    M -->|"命中<br/>详情 6h · 列表 30min"| RET["返回渲染 HTML<br/>X-Prerender: hit"]
    M -->|"未命中"| P{"详情页：内容存在？<br/>（直连 app API 探测）"}
    P -->|"不存在 / 未发布"| R404
    P -->|"存在"| R["Chromium 渲染<br/>串行队列 · 每 50 页重建浏览器"]
    R --> S["写缓存并返回<br/>X-Prerender: miss"]
    R -.->|"内存达阈值 / 队列超限 / 渲染失败"| SHELL["降级：回源拉取 SPA 壳<br/>返回 200 不写缓存"]

    GB["Googlebot（自带 JS 渲染，刻意不分流）"] --> SPA["nginx try_files SPA 兜底"]
```

补充：

- AI 爬虫（GPTBot / ClaudeBot / PerplexityBot 等）不执行 JS，必须预渲染，属 GEO 关键路径；`llms.txt` 与 IndexNow 端点同属此链路。
- 预渲染服务自身回源 UA 不命中 nginx bot map，防渲染请求无限自循环。
- 非爬虫的真实用户永远只拿静态产物，预渲染故障不影响真人访问（nginx 对 prerender 只要求 started 不要求 healthy）。

## 七、发版与 CI 流水线

CI 不直接部署；发版为人工在服务器执行 tar 包流水线。

```mermaid
flowchart LR
    DEV["开发者 push"] --> CI["GitHub Actions · 4 job<br/>后端离线测试与静态自检<br/>迁移正反向（真实 MySQL）<br/>前端矩阵 · 镜像构建"]
    PACK["本机 pack-deploy.sh<br/>git archive 白名单 + 自检"] --> TAR["部署 tar 包"]
    TAR --> DEPLOY["服务器 deploy.sh"]

    DEPLOY --> B["强制预发版备份<br/>失败即终止"]
    B --> S[":prev 镜像快照"]
    S --> U["只停应用层 · 串行构建<br/>compose up"]
    U --> G{"四道门禁<br/>健康 / 统计后台 / 深健康 / 内容冒烟"}
    G -->|"通过"| DONE["发布完成 · 清理旧镜像"]
    G -->|"失败"| DIAG["输出诊断与回滚指引<br/>（不自动回滚）"]
```

门禁语义：健康与统计门禁阻断发版；深健康只报告不阻断（Redis 故障属优雅降级）；内容冒烟只判 5xx（401/403 是正常权限语义）。
