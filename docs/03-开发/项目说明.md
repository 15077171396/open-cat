## 一、项目概述

### 1.1 项目定位

本书库是 AI学习猫（www.wdmao.cn）的**后台管理端开源版**：一套自带按钮级 RBAC、全量操作审计、UGC 审核与 AI 写作的内容运营底座。

内容管理只保留 **教程** 一条完整链路作为**示例业务域**（列表 → 章节树 → 编辑 → 预览 → 发布 → 审核 → 回收站），其余内容形态靠脚手架复制：

| 模块 | 定位 | 内容形态 |
|------|------|---------|
| **教程** | 示例业务域（可照抄的样板） | 多章节结构化课程，支持免费 / 会员 / 积分购买三级权限 |
| **分类** | 内容归类 | 左栏分组 + 右栏分类，分组只在后台使用，不参与前台筛选 |
| **素材库** | 图片资产池 | 上传 / 图库导入 / AI 图统一浏览与复用 |

原站另有「在线工具 / 资源下载 / 节点百科 / 扩展」四个领域模块，已在通用化改造中下线（代码、路由、权限码、数据表均不再随仓库分发）；需要同类能力时用
`python scripts/new_module.py <模块名> --label <中文名>` 生成五件套，再按[开发文档](../07-开源文档/05-开发文档.md) §5.0 的清单登记 8 处注册表。

配套三端：**PC 用户端**（frontend）、**后台管理端**（admin-frontend）、**微信小程序**（miniprogram）。开源版交付范围为**后端 + 管理后台**。

### 1.2 商业模式

采用「**免费引流 + 知识星球深度转化**」双轨制：

- **核心内容**：教程提供 **3 小时免费体验**（自然时间窗口），耗尽后需通过**知识星球认证**解锁无限访问；
- **积分体系**：积分购买教程消耗积分；兑换码 / 邀请返利获取积分。

> **实现对照（2026-10-27 更新 —— 已新增站内登录与在线支付）**
>
> 知识星球认证仍然保留；同时新增**手机号验证码登录、微信扫码登录、在线支付**，
> 全部通过后台「系统 → 登录管理 / 系统 → 支付与渠道」动态开关与配置，
> 未配置资质时自动隐藏/拒绝。
>
> | 环节 | 代码落点 |
> |---|---|
> | 3 小时免费窗口 | `users.free_started_at` + `config.FREE_TIME_LIMIT = 10800`，按**自然时间**倒计时（不是累计学习时长） |
> | 知识星球认证 | `auth_requests` 表（`star_code` 字段）+ `services/audit_service.py` + 管理端审核台；前端 `/auth` 页即申请入口 |
> | 认证通过 → 会员 | 管理端审核通过后写 `users.vip_expire_time`（`role` 转 `vip`）—— **全站会员权益由这一个字段驱动** |
> | 手机号验证码登录 | `users.phone` + `services/phone_auth_service.py` + `services/sms/`（Mock / 腾讯云 / 阿里云三通道）；未注册号码按后台开关自动建号或要求先绑定 |
> | 微信扫码登录 | `services/social_auth_service.py` + `users.wechat_unionid / wechat_web_openid`；小程序登录也按 unionid 优先合并账号 |
> | 积分 | `point_transactions` 流水。入金口为**在线充值**（`payment_orders` → `recharge` 流水）+ 兑换码 + 邀请返利 |
> | VIP 购买 | `payment_products(kind=vip)` → 支付回调后按现有叠加逻辑延长 `users.vip_expire_time` |
> | 在线支付 | `payment_products` / `payment_orders` + `services/payment_service.py` + `services/payments/`（Mock / 微信支付 v3 Native / 支付宝电脑网站）；用户端 `/recharge`，管理端 `/payment-products` 与 `/payment-orders` |
> | 教程付费 | `tutorials.access_mode`（`free` / `vip`）+ `points_price`；非会员可用积分永久购买单篇 |

### 1.3 角色权限体系

角色为四级，另有**企业级 RBAC**（角色-权限-部门）叠加在 `admin` 之上：

| 角色 | 等级 | 核心权限 | 触发条件 |
|------|------|---------|---------|
| `guest` | 0 | 浏览所有列表页、查看简介 | 未登录 |
| `user` | 1 | 查看/使用教程（3 小时上限） | 完成注册 |
| `vip` | 2 | 无限时访问教程 | 知识星球认证通过 |
| `admin` | 3 | 后台全部功能，实际可操作范围由 RBAC 权限点决定 | 后台分配 |

> `admin` 的内部权限由 `roles` / `permissions` / `role_permissions` / `user_roles` / `departments` 五张表驱动，详见 [5.5 节](#55-权限体系rbac)。

## 三、代码规模与目录结构

### 3.1 规模总览（实测）

> 统计口径：**「后端 N 行」= `backend/app/` 下 `.py` 源码行数**（不含 `tests/`）；
> ⚠️ 2026-10-13 及更早版本的 28,076 行是 `backend/` 全目录口径（**含测试代码**），与本节自述不符，已按本节口径修正（现值见上表）。
> 前端行为 `frontend/src` / `admin-frontend/src` 下 `.ts` + `.tsx` 行数。用例数用 `pytest --collect-only` / vitest 自动收集，不手数。

| 模块 | 规模 | 明细 |
|------|------|------|
| 后端 | **≈4.6 万行** Python（`app/`） | `app/api/` 下 51 个 `.py`（**47 个含路由的模块** + `router.py` 聚合与 2 条健康探针 + `_admin_shared.py` 共享层 + `__init__.py`；`admin.py` 为聚合入口、自身 0 路由）/ **182 条路径 · 221 个操作**（`app.openapi` 实测）/ 77 个 service / 26 个 model 文件 / 37 张表 / 80 个迁移 |
| 用户端 | **19,150 行** TS/TSX | 25 个页面组件 / **26 条路径路由**（共 29 个 `<Route>`，含布局壳与 404 兜底） |
| 管理端 | **25,845 行** TS/TSX | 23 个页面模块（35 个 `.tsx`）/ **34 条 `path` 路由**（含登录与 404 兜底） |
| 小程序 | 24 个页面 | WXML + WXSS（TDesign），2 个自建组件（`list-footer` / `profile-header`） |
| 测试 | **1699 个用例** | 138 个测试文件（后端，另有 `conftest.py` 夹具与 `fake_db.py` 内存会话仿真）；管理端另有 **313 个 vitest 用例 / 37 文件**（编辑器组件与工具函数）；用户端 **30 个 vitest 用例 / 4 文件** + 41 项错误监控脱敏回归、预渲染 10 项内存降级回归；小程序无自动化测试 |

> ⚠️ **「182 条路由」的口径说明**：早年文档写的「182 条路由」= 当年 OpenAPI 的 179 个操作 **+ 3 条 app 级路由**（`/openapi.json`、`/docs`、`/redoc`，不计入 OpenAPI 自身）。本节统一为 **OpenAPI 口径 212 路径 / 260 操作**，与 `app.openapi` 输出逐一对齐（由 `scripts/check_doc_stats.py` 在 CI 中守卫，数字对不上直接红）；引用旧值时请以本节为准。

### 4.2 主键约定

⚠️ **全库主键均为非自增的 10 位随机数字**（`1000000000 ~ 9999999999`），由 `backend/app/database.py::generate_id` 用 `secrets.randbelow` 生成，目的是**避免自增 ID 被枚举爬取**。

```python
def generate_id -> int:
    return secrets.randbelow(9_000_000_000) + 1_000_000_000
```

外键仍为 `BigInteger`，但**无数据库级 FK 约束**（应用层维护），便于分库分表演进。

### 4.4 迁移

共 **80 个** Alembic 迁移文件（按 `2026…_00NN_` 序号命名 73 个，序号到 **0069**；早期 hash id 命名 7 个）。序号存在少量**重复占用**（`0001` / `0028` / `0029` / `0045` 各被两个不同日期的迁移使用——文件名含日期不会冲突，Alembic 亦以 revision id 而非序号定位，但阅读与回滚定位时不要拿序号当唯一标识），**单 head**（`drop_legacy_content_tables`；`tests/test_admin_audit.py` 有硬编码棘轮断言，新增迁移必须同步改它）。`0069` 已在真实 MySQL 8.4 上验证 `upgrade head → downgrade -1 → upgrade head` 往返。生产环境由 `migrate` 一次性容器执行 `alembic upgrade head`，`app` 服务依赖其成功完成才启动。

⚠️ **含改名/删列的迁移使代码与 schema 双向锁定**（`20261012_0038` 把 `tutorial_comments` 改名为 `content_comments`，`0040` 删掉 plugins 四列）：回退代码镜像时，旧代码的 alembic 目录里**没有**这些新 revision，`upgrade head` 会以 `Can't locate revision` 失败 → `migrate` 非零退出 → `app`/`nginx` 依 `depends_on` 永不启动。即「只回滚代码」不成立，必须连 schema 一起退（或恢复发版前备份），见 [部署说明书](../04-运维/部署说明书.md) 10.5。

## 五、后端架构

### 5.1 应用入口

`backend/app/main.py::create_app` 注册顺序：**CORS → 限流 → 异常处理 → 路由**。

- 生命周期：启动打印环境信息，关闭释放 Redis 连接；
- 开发环境启用 `/docs` 与 `/redoc`，**生产环境自动关闭**。

### 5.2 配置管理

基于 `pydantic-settings` 从 `.env` 读取。核心项：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `APP_ENV` | development | 环境 |
| `SECRET_KEY` | — | JWT 密钥（生产必须替换，否则拒绝启动） |
| `JWT_ACCESS_EXPIRE_MINUTES` | 120 | Access Token 有效期 |
| `JWT_REFRESH_EXPIRE_DAYS` | 7 | Refresh Token 有效期 |
| `FREE_TIME_LIMIT` | 10800 | 免费时长上限（3 小时，秒） |
| `AI_DAILY_LIMIT_PER_USER` | 50 | 单用户单日 AI 调用上限 |
| `AI_TIMEOUT_SECONDS` / `AI_RETRY_COUNT` | 30 / 2 | AI 调用超时与重试 |
| `SITE_BASE_URL` | — | 站点基址（sitemap / canonical 用） |
| `BAIDU_PUSH_TOKEN` / `INDEXNOW_KEY` | — | 搜索推送凭据 |
| `CORS_ORIGINS` / `TRUSTED_PROXIES` | — | 跨域白名单 / 可信代理（影响限流取真实 IP） |

> **运行期可改配置**：后台「系统设置」写入 `system_settings` 后，由 `runtime_config` 在进程内覆盖
> 同名 Settings 值（env 只作启动兜底，覆盖失败保持现状），多 worker 经 60s 轮询同步——
> 改后台设置无需重启；反过来 `.env` 改动必须重启才生效。

### 5.3 数据库与 Redis 连接

- **MySQL**：`create_async_engine`，`pool_size=10`、`max_overflow=20`、`pool_recycle=3600`、`pool_pre_ping=True`；
- **Redis**：`decode_responses=True`、`max_connections=20`、`protocol=2`。

⚠️ **Redis 容灾策略**：项目对缓存 / 防刷 / 限额均做了 **try/except 降级**（缓存失效直查 DB、防刷降级放行、限额 fail-open），Redis 故障时公开接口不会 500。

### 5.4 认证与安全

| 项 | 方案 |
|----|------|
| 密码 | bcrypt（自动截断 72 字节），走 `asyncio.to_thread` 不阻塞事件循环 |
| JWT | HS256；access 2h + refresh 7d（Redis 存储，可吊销） |
| 登出 | 删除 Redis refresh_token（⚠️ **access token 在有效期内仍可用**，见第十章待办） |
| 验证码 | 6 位数字、5 分钟过期、Redis 存储、同账号 60s 限频、**按 IP 日配额 20 次** |
| 登录锁定 | 连续失败 10 次锁定账号 15 分钟（Redis 故障时 fail-open） |
| 注册防枚举 | 验证码校验**优先于**账号存在性检查 |
| 限流 | Redis ZSET 滑动窗口：游客 120 次/分钟，登录用户 300 次/分钟 |
| 上传 | 扩展名白名单 + 魔数一致性校验 |
| 富文本 | nh3 白名单净化 + `data:` URL 双重过滤 |
| 图片代理 | 协议 + 域名精确白名单、手动逐跳重定向且每跳重校验、**排除 SVG**（防同源 XSS） |

### 5.5 权限体系（RBAC）

`backend/app/core/rbac.py` + `api/admin_rbac.py`，企业级组织架构：

- 五张表驱动：`roles` / `permissions` / `role_permissions` / `user_roles` / `departments`；
- 管理端页面按权限点门控（前端 `PermGuard.tsx` + `can('xxx:view')`）；
- `require_admin` 为 **fail-closed**（异常即拒绝）。

同时保留轻量角色依赖：`require_user` / `require_vip` / `require_admin`。

### 5.7 定时任务

`backend/scheduler/tasks.py`，APScheduler（**独立容器**运行，与 API 进程分离）。

**调度是配置驱动的**（2026-10-27 起）：把「代码里注册的 handler」与「库里保存的配置」合并后注册。

| 层 | 位置 | 说明 |
|----|------|------|
| 任务清单（代码） | `services/scheduled_job_service.py::JOB_SPECS` | 周期默认值 / 超期阈值 / 依赖配置 / 说明，**唯一事实来源** |
| 任务体（代码） | `scheduler/tasks.py::JOB_FUNCS` | id → handler，**新增任务必须在这里注册**（测试与 JOB_SPECS 双向比对） |
| 可配置项（库） | 表 `scheduled_job_configs` | `enabled` / `schedule_kind` / `hour` / `minute` / `interval_minutes` |
| 生效状态（Redis） | `ops:jobs:applied` | 调度器每 5 秒写回「我按哪份配置在跑」+ 存活心跳（TTL 120s） |
| 手动执行（Redis） | `ops:jobs:commands` | 后台「立即执行一次」的命令队列，调度器每秒 `LPOP` 一条 |

| 任务 | 默认触发（Asia/Shanghai） | 说明 |
|------|------|------|
| VIP 过期降级 `check_vip_expiry` | 每日 02:00 | `role='vip' AND vip_expire_time < NOW` → 降级为 `user` |
| 百度收录推送 `push_new_urls_to_baidu` | 每日 03:00 | 推送近 26h 新增/更新 URL；`BAIDU_PUSH_TOKEN` 未配置时自动跳过 |
| IndexNow 推送 `push_new_urls_to_indexnow` | 每日 03:10 | 向 Bing/Yandex 等推送；`INDEXNOW_KEY` 未配置时自动跳过 |
| 审计日志清理 `cleanup_audit_logs` | 每日 04:00 | `admin_audit_logs` 保留 365 天 |
| 搜索日志清理 `cleanup_search_logs` | 每日 04:30 | `search_logs` 保留 90 天 |
| 浏览归因清理 `cleanup_content_views` | 每日 04:40 | `content_views` 保留 180 天 |
| 数据质量巡检 `data_quality_check` | 每日 05:00 | 只查不删；结果写 Redis，供后台展示 |
| 浏览量落库 `flush_view_counts` | 每 1 分钟 | Redis 累加 → 合并成一条 UPDATE，写放大降到 1/60 |

上表是**代码默认值**；后台「系统 → 定时任务」可改周期与启停（超期阈值随调度类型固定：日报 26h、每分钟 30min）。

**后台能做什么**（页面：系统 → 定时任务）：
- **启停**、**改周期**：写 `scheduled_job_configs`，调度器每 5 秒比对配置指纹后热重载（**不用重启容器**）。
  页面顶部会显示「等待生效」直到对齐完成 —— 保存 ≠ 生效，这一点必须显式。
- **立即执行一次**：命令入队 → 调度器执行。**调度器没在跑时接口直接 503**，不假装成功。
- **不能新增/删除任务**：任务体是代码，新增一种任务 = 一次代码变更（有测试、审查、回滚）。

**观测**：
- 每次执行结束由 `_run_guarded` 写 Redis `ops:job:<id>`（TTL 3 天，**不是审计留痕**）；
- 四态 `ok / failed / stale / never` + `disabled`，阈值与停用判定都在 `scheduled_job_service` 单点决定；
- 同一任务**不并发**（进程内闩锁，调度触发与手动触发共用）；
- 已停用的任务不再产生「未按时执行」告警（人主动关的，不是故障），但页面长期显性标注。

**权限**：读 `dashboard:view`（与其他只读运维接口同层级），写 `scheduler:manage`（超管默认持有，
内容管理员与只读管理员**不授予**，需要时在角色管理里显式勾选）。写操作全部落审计
（`scheduled_job_update` 记 from/to；`scheduled_job_run`）。

⚠️ 时区已显式指定（为北京时间），未指定时容器按 UTC 执行，实际会晚 8 小时。
⚠️ 本机开发没有 scheduler 容器：`scripts/start-scheduler.bat` 手动起；不起也能用页面，但「立即执行」会 503。

## 八、核心业务流程

### 8.1 注册与登录

```
POST /auth/send-code {account}
  → 校验手机号/邮箱格式 → 6 位验证码存 Redis(5min) → 60s 发送间隔 → 按 IP 日配额 20 次

POST /auth/register {account, password, code}
  → 校验验证码（优先于账号存在性检查，防枚举）
  → bcrypt 哈希 → 创建 User(role=user, free_started_at=now)
  → 生成 access + refresh → refresh 存 Redis(7d)

小程序：POST /auth/miniapp/login {code} → wx.login code 换 openid → 绑定或创建账号
```

#### 登录二次验证（TOTP）

```
POST /auth/login（账号已开启 TOTP）
  → 未带 totp_code → 401 { data: { totp_required: true } }，前端弹出验证码输入框
  → 校验顺序：先比 TOTP（RFC 6238），不中再比恢复码（sha256 命中即从列表摘除，一次性）
  → 失败独立计数：连续 5 次锁 15 分钟（与密码失败计数分开；Redis 故障 fail-open，同登录锁定口径）
```

### 8.2 免费时长计时

**现行模型是「自然时间窗口」，不是「累计使用时长」**：

```
判定：now - free_started_at >= FREE_TIME_LIMIT(10800s) → 免费额度耗尽
     —— 不在线也计时，注册即开始倒计时

free_used_seconds 仅作为「实际学习时长」统计，不参与判定
```

> 该口径于 2026-08-18 变更。看板转化率分母已同步改为自然时间口径，否则指标恒为 0。

**时长上报只有小程序端**（Web 用户端不调用 `/track`）：

```
小程序 pages/tutorial-read：setInterval 每 10s → POST /tutorials/{id}/track {duration: 10}
  → check_and_consume：VIP/admin 跳过；防刷（Redis track:{user_id} 10s 标记）
  → 累加 free_used_seconds → 返回 {free_used_seconds, free_remaining_seconds, is_exhausted}
  → 超限抛 FreeTimeExhaustedError（403 + need_auth）→ 前端弹认证弹窗

Web 用户端：无任何时长上报（`frontend/src` 全量 grep `/track` 零命中，
  TutorialDetail 只调 /tutorials/{id}/purchase）
```

> **由此产生的口径后果**（2026-10-11 实测）：`free_used_seconds` 只对**小程序用户**累积，
> Web 端用户该列恒为 0 / 初始值。它目前的消费点只有两处，**都不受影响于全站指标**：
> ① 管理端用户列表与详情的「已学时长」展示（`admin_user_service.py`，逐用户读该列 —— 注意 Web 用户会显示 0，不是 bug 而是没上报）；
> ② `GET /auth/me` 的回显。
> ⚠️ 曾经有第三处消费点已修掉：2026-08-18 之前看板「3 小时体验转化率」按 `free_used_seconds >= FREE_TIME_LIMIT`
> 统计耗尽用户，按 `free_started_at` 的自然时间窗口口径统计（不依赖上报累加）：
> （`stats_service.py` 有注释钉住这个口径，**改回旧口径会让指标再次失真**）。
> 判定免费额度是否耗尽同样走自然窗口，与上报无关。

### 8.3 知识星球认证

```
状态机：
  用户提交 → pending → approved（管理员通过，设时长 1month/3month/1year）
                    │           └→ vip_expire_time 到期 → 定时任务降级为 user
                    └→ rejected（驳回，可重新提交）

提交：POST /auth/star/submit {star_code} → 查重 → 建 AuthRequest(pending)
审核：PUT /admin/auth-requests/{id}/approve {vip_duration}
     → now + 30/90/365 天 → user.role='vip'
     ⚠️ 带时区偏移的输入会归一化为 UTC 后再落库（naive 列统一存 UTC）
```

### 8.4 资源获取

```
游客：GET /resources/{id} → netdisk_links = []（不含链接）
登录：POST /resources/{id}/get-links
     → 查 resource_netdisk_links（按 sort_order）
     → 记录 Download + download_count += 1（原子自增）
     → 返回 [{platform, url, extract_code}]
前端：渲染链接列表 + 提取码一键复制
```

### 8.5 教程三级权限与积分购买

```
GET /tutorials/{id}
  → access_mode == 'free'                → 放行
  → access_mode == 'vip' 且 VIP 有效     → 放行（is_vip_effective 即时校验）
  → access_mode == 'vip' 且已积分购买     → 放行（tutorial_purchases 命中）
  → 否则                                 → 403，返回 points_price 引导购买

POST /tutorials/{id}/purchase
  → 先插 tutorial_purchases（唯一约束做并发幂等兜底）
  → 再原子扣积分（UPDATE users SET points = points - price WHERE points >= price）
  → 写 point_transactions 流水
```

### 8.6 积分与兑换码

- **获取**：兑换码兑换、邀请返利、管理端调整；
- **消耗**：运行积分工具、积分购买教程；
- **流水**：`point_transactions` 记录 `amount` / `balance_after` / `type` / `operator_id`，**扣减后回读真实余额再写流水**（消除陈旧内存值）；
- **兑换码**：单人码 / 多人限量码，并发安全兑换（`used_count` 原子自增 + 配额校验）。

### 8.7 邀请返利

```
用户访问 /profile/invite → 惰性生成 invite_code
新用户注册携带邀请码 → 绑定 referrer_id → 写 invite_relations → 双方获得积分
查询：GET /users/invite/info · /users/invite/invitees
邀请海报：GET /users/invite/poster → 1080×1440 PNG（Pillow 合成 + 二维码，
二维码内容即 /login?invite=<code>；头像优先走服务端凭证读 COS，失败回落昵称首字）
```

> 海报在**服务端**出图（`services/invite_poster.py`）：字体/间距/二维码清晰度不依赖
> 用户设备；镜像需装 `fonts-noto-cjk`，缺字体时会直接抛错而不是画出方块。

### 8.8 消息中心

`messages` 表 + `notification_settings` 通知偏好；支持未读数、单条已读、全部已读、删除。

内容**下架**时会自动给「收藏过它」的用户发一条系统消息（`services/content_notify.py`，与下架操作同事务）；
消息**不带链接** —— 目标已不可访问，给链接等于把用户送进 404。

### 8.9 AI 工具运行

```
POST /tools/{id}/run {input_data}
  → 查 Tool（必须 is_published）
  → AI 工具：检查每日上限 ai_daily:{user_id}:{YYYYMMDD} >= 50 → 429
  → check_and_consume 计时 → 超限抛 403
  → 记录 ToolUsageLog
  → 渲染 prompt_template（输入字段 ≤ 20 个，单值 ≤ 2000 字符）
  → 调用 Provider（带重试）→ 增加每日计数
  → 积分工具：原子扣费
  → 返回 {result, tool_name}
```

> AI 响应结构做校验：限流 / 风控（HTTP 200 + `{"error":...}`）与空内容均转为明确的 503 业务错误，不落 500。

| 管理操作审计 | `admin_audit_logs` 表 + 12 类敏感动作埋点，与业务同事务落库 |
| 二次验证（TOTP） | `users.totp_secret`（**加密存储**）+ `totp_enabled` + 一次性恢复码哈希。自实现 RFC 6238（零依赖，对齐官方测试向量）；绑定分两步（先写密钥、验证通过才启用）；TOTP 失败独立计数（5 次锁 15 分钟）；关闭需验密码。绑定入口在管理端「个人中心 → 安全设置」 |
| 内容归因 | `content_views` 记录**登录用户**的内容浏览（按天去重），回答「看过它的人里有多少在 7 天内申请了认证」。写入走 `INSERT IGNORE` + SAVEPOINT，**埋点失败不影响详情页**；用户 id 从请求上下文（contextvar）取，不透传到 service 签名 |
| 会话收敛 | `POST /auth/logout-all` 提升令牌版本号 → 所有已签发 access/refresh 立即失效。⚠️ 每账号只存一个 refresh_token，故提供「退出全部设备」而非逐台管理 |
