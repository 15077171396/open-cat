## 一、抄什么、不抄什么

gi-demo 的视觉基线由四条结构纪律决定：**蓝色主色 + 橙色点缀、4px 小圆角、浅灰画布 + 白色页面卡、多标签页**。颜色只是表层，布局密度与卡片层次才是"像不像"的关键。

| 抄（结构纪律） | 理由 |
|--------------|------|
| 主色 `#165DFF`、装饰橙 `#FF9A2E`、画布 `#F5F7FD` | 与参考项目同源，实心按钮白字 5.15:1 达 AA |
| 卡片/控件 **4px 圆角**、卡片**无阴影** | 后台信息密度高，小圆角更利落 |
| 卡片标题左侧 4px 橙色竖条、标题 16/500 | gi-demo 的识别特征 |
| 顶栏 56 + 标签页 32 + 页面卡 + 16px 内边距 | 一屏结构与参考项目一致 |
| **多标签页**：首页固定、可关闭、可刷新、可关闭其他 | 后台高频切换页面，标签页是效率结构 |
| 表格：表头 `#FAFAFA` / 13px、行高 44、无竖分隔线 | 表格是后台主战场，规格必须统一 |
| 状态标签**胶囊形**（22px）、普通标签 4px | 参考项目的语义标签形态 |
| 一个区域只允许一个实心主按钮 | 视觉层级清晰 |
| 破坏性操作只用危险色（`#CF1322` 达 AA） | 比 gi-demo 的 `#F53F3F` 更易读 |

| 不抄（或改造后采用） | 原因 |
|--------------------|------|
| 强制 i18n（禁止硬编码中文） | 已落地基础 i18n，但业务页面文案量大，仍按页迁移 |
| 移动端全量卡片化 | 后台用户主要在桌面；只对已有三页做响应式 |
| Tailwind + SCSS 双样式体系 | 用 **AntD token + CSS 变量** 达到同样效果 |
| 可拖拽分栏 / splitter | 参考项目也明确禁止，一致 |
| Hash 路由 | 我们用 history 模式（`base=/admin/` 已配好 nginx） |

| 用途 | 色值 | 白底对比度 | 说明 |

| 主色 active | `#0E42D2` | — | |

## 三、布局规范

### 3.1 骨架

```
┌ 侧栏 220 ┬ 顶栏 56：折叠 · 面包屑 · 搜索/待办/语言/主题/布局/头像 ┐
│ logo 56  │ 标签页 32：首页 × | 用户管理 × | ...      刷新 · 关闭 ▾  │
│ 菜单     ├──────────────────────────────────────────────────────┤
│          │ 画布 #F5F7FD，padding 16                              │
│          │ ┌ 白色页面卡 radius 4 ─────────────────────────────┐  │
│          │ │ 页头：标题 + 副标题 ·············  操作按钮      │  │
│          │ ├──────────────────────────────────────────────────┤  │
│          │ │ 工具条 / 表格 / 表单（16px 内边距）              │  │
│          │ └──────────────────────────────────────────────────┘  │
└──────────┴──────────────────────────────────────────────────────┘
```

- 看板页（`/`、`/workplace`、`/analysis`）画布直铺卡片，不套白色页面卡。
- 列表 / 表单 / 设置 / 编辑页：白色页面卡 + 全宽卡头（页头底边线）。
- 编辑页：页面卡上下内边距为 0，保证编辑器工具栏吸顶。

### 3.2 多标签页

- 首页 `/` 固定为第一个标签，不可关闭。
- 访问过的路由自动加入；标签 key 用完整 `pathname`（含动态 id）。
- 标题优先级：`PageHeader` 注册的标题 → 菜单名 → `tabs.untitled`。
- 关闭当前标签跳到左侧相邻标签；关闭其他 / 关闭全部始终保留首页。
- 刷新只重新挂载当前页面，不整页 reload。
- 上限 10 个；`sessionStorage` 键 `ai_cat_admin_tabs`；权限/菜单变化后丢弃已不存在的入口。
- 移动端隐藏标签条，保留抽屉菜单。

### 3.3 一屏布局（硬规则）

```tsx
// 页面根节点承担「满高 + 内部滚动」
<div style={{ height: '100%', display: 'flex', flexDirection: 'column', gap: 16 }}>
  <PageHeader />                                {/* shrink-0 */}
  <FilterBar />                                 {/* shrink-0 */}
  <ToolbarBar />                                {/* shrink-0 */}
  <Card style={{ flex: 1, minHeight: 0 }}>      {/* 可伸缩 */}
    <Table scroll={{ y: 'calc(100% - 56px)' }} /> {/* 只在卡片内部滚 */}
  </Card>
</div>
```

四条约束：

1. **禁止魔法高度**：不允许 `height: 520`、`maxHeight: 52vh` 决定一屏结构；
2. **固定区 `flex-shrink: 0`**（标题、筛选、工具栏）；
3. **伸缩区 `flex: 1; min-height: 0`**（表格、图表）；
4. **页面本身不出现第二条滚动条**——`html/body` 在后台布局内不滚动。

> 现状问题：`AdminLayout` 用 `position: fixed` + `height: 100vh` + Content `margin: 24`，滚动发生在 Content 外层，导致长列表时筛选条会被滚走。改造点是给 `Content` 内层一个 `height: 100%` 容器并接管滚动。

## 四、页面模板

### 4.1 列表页（覆盖 20+ 页）

```
┌ PageHeader ────────────────────────────────────────────┐
│ 标题 + 一句话说明                        [次要操作][主操作] │
├ FilterBar ─────────────────────────────────────────────┤
│ [搜索框] [下拉筛选] [日期范围] [重置][查询]              │
├ ToolbarBar ────────────────────────────────────────────┤
│ 已选 N 项：批量发布 | 批量删除        共 128 条 · 刷新   │
├ Table ─────────────────────────────────────────────────┤
│ 名称(弹性) 分类(120) 状态(100) 时间(190) 操作(180 固定右) │
└────────────────────────────────────────────────────────┘
```

- 换筛选**必须清空已选**（防"删掉看不见的行"，现有代码已实现，改造时保留）；
- 空态：隐藏分页 + 显示插画/文案 + 主操作按钮；
- 批量操作条只在有选中时出现，不占常驻高度。

### 4.2 编辑页（覆盖 15+ 页）

```
┌ 顶部固定 56：返回 | 标题 | 状态标签 ……… 预览 | 保存 ┐
├──────────────────────────┬─────────────────────────┤
│ 主区（弹性，可滚动）      │ 侧区 320 固定            │
│ 标题 / 正文 / 章节        │ 分类 / 状态 / SEO / 封面 │
└──────────────────────────┴─────────────────────────┘
```

- 侧区在 `<1280px` 时移入折叠面板，**不做 splitter**；
- 离开前未保存提示（`useUnsavedChangesGuard` 已有）；
- 保存按钮 loading，禁止整页遮罩。

### 4.3 设置页（26 组 138 项）

```
┌ 左分类 200 ┬ 分组标题 + 保存 ─────────────┐
│ 基础        │ 字段（label 右对齐，统一宽度） │
│ 内容与检索  │ 说明文字走 colorTextTertiary  │
│ 媒体        │ [测试连接]                   │
└────────────┴──────────────────────────────┘
```

- 未保存分组在左侧栏打小圆点（现有 `dirtyGroups` 已有）；
- 密钥类字段：默认掩码，聚焦后可改，**回车不提交**。

### 4.4 看板（已实现，仅调密度）

- 指标卡 4 列（`<1280px` 2 列），卡内 padding 16；
- 图表必须给容器**可测量高度**（`minHeight: 280`），否则 ECharts 初始化空白；
- 系统状态卡用状态点 + 文本，不用进度条。

## 六、状态与语义

| 语义 | 颜色 | 用于 |
|------|------|------|
| 主操作 | Primary | 新增、保存、查询、运行中 |
| 成功 | `#16A34A` | 已发布、成功、已连接、正常 |
| 警告 | `#D97706` | 待处理、超时、额度将尽 |
| 危险 | `#CF1322` | 删除、停用、强制下线（**仅破坏性**） |
| 信息/中性 | 灰 | 草稿、已取消、未执行 |

规则：

- **一个区域只允许一个实心主按钮**，其余用默认/文字按钮；
- 状态标签高度 22、字号 12、**圆角胶囊 999**；普通标签 4px 圆角；
- 破坏性按钮默认透明 + 危险色文字 + 浅红描边，hover 淡红底，**禁止灰底**；
- 定时任务四态（正常/上次失败/未按时执行/从未执行）必须用四种不同语义色，不可复用。

## 八、为什么不用 Tailwind

参考项目用 `Tailwind 4 + SCSS + Element Plus 变量` 三套并存。我们不引入 Tailwind：

1. AntD 6 已有完整的 token 体系（`theme.token` / `components`），能覆盖 90% 需求；
2. 引入 Tailwind 会出现"哪个类优先"的持续争论，新人成本高；
3. 关键少数场景（一屏布局链）用 3 个 CSS 变量即可：
   ```css
   :root {
     --app-gap: 16px;
     --app-radius: 4px;
     --app-header-h: 56px;
   }
   ```
4. 真要上原子类，也是在 token 稳定之后的事，不是现在。
