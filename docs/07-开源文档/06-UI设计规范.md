> 项目：AI 学习猫 · 后台管理端
> 版本：v1.0　更新：2026-10-29
> 参考：[FastapiAdmin `design/UI-GUIDELINES.md`](https://github.com/fastapiadmin/FastapiAdmin/blob/master/design/UI-GUIDELINES.md)（设计系统层面）

> 配套：[功能文档](01-功能文档.md) · [开发文档](05-开发文档.md)

## 一、抄什么、不抄什么

参考项目的视觉讨喜，**根源不在配色，而在三条结构性纪律**：`16px 间距 + 12px 圆角 + 一屏内部滚动`。这三条决定了"整洁感"，颜色只是点缀。

| 抄（结构纪律） | 理由 |
|--------------|------|
| 卡片间距 16 / 页面内边距 16 / 卡片圆角 12 | 一致性来自固定节拍，不是审美 |
| **一屏布局内部滚动**，页面不出现第二条滚动条 | 后台最高频的观感问题 |
| **禁止魔法高度**（`h-150`、`52vh`） | 换屏就塌，是响应式灾难的源头 |
| 表格规格：行高 40 / 表头 44 / 时间列 190 / 操作列 180 固定右 | 表格是后台的主战场，规格必须统一 |
| 状态标签语义色表 | 避免"危险色表示普通状态"这类误读 |
| 一个区域只允许一个实心主按钮 | 视觉层级清晰 |
| 破坏性操作只用危险色（默认透明 + 红字 + hover 淡红） | 比灰底删除更难误点 |
| 空态 / 骨架屏 / 分页的统一落位 | 消除"每个页面自己发明一套" |

| 不抄（或改造后采用） | 原因 |
|--------------------|------|
| 强制 i18n（禁止硬编码中文） | 我们当前无 i18n，硬上会让 50 个页面全部改动。改为：**文案集中到常量文件**，为后续 i18n 留口 |
| 移动端全量卡片化（<1025px） | 后台用户 95% 在桌面；只对「评论 / 举报 / 反馈」三页做响应式 |
| Tailwind + SCSS 双样式体系 | 引入第二套样式方案会增加心智负担。用 **AntD token + CSS 变量** 达到同样效果 |
| 可拖拽分栏 / splitter | 参考项目也明确禁止，一致 |
| Hash 路由 | 我们用 history 模式（`base=/admin/` 已配好 nginx） |

## 二、设计 Token

### 2.1 品牌色（三选一，改一处即可切换）

| 方案 | 主色 | 白底对比度 | 适用 |
|------|------|-----------|------|
| **A（已落地）** | `#4263EB` | **4.94:1 ✅ AA** | 观感接近参考项目，且实心按钮白字达标 |
| B | `#4F6BFF` | 4.24:1（仅 AA Large） | 参考项目同款；若不在意按钮文字对比度可直接换 |
| C | `#1677FF` | 3.90:1（不达标） | 保留 AntD 默认，不推荐 |

> **为什么默认不是参考项目的 `#4F6BFF`**：它作实心按钮底色时白字只有 4.24:1，低于 WCAG AA 正文要求的 4.5:1。降到 `#4263EB` 后为 4.94:1，观感几乎无差别。这与现有代码里"`colorError` 用 red-7 而非 red-5"是同一套取舍。
> 切换方法：只改 `src/theme.ts` 的 `BRAND.primary`。

## 三、布局规范

### 3.1 骨架

```
┌────────┬──────────────────────────────────────────┐
│        │  顶栏 56px：折叠按钮 · 面包屑 · 右操作区   │
│ 侧栏   ├──────────────────────────────────────────┤
│ 220px  │  内容区 padding 16                        │
│        │  ┌────────────────────────────────────┐  │
│ 分组   │  │ 卡片 radius 12 · 卡片间距 16        │  │
│ 菜单   │  └────────────────────────────────────┘  │
└────────┴──────────────────────────────────────────┘
```

### 3.2 一屏布局（硬规则）

```tsx
// 页面根节点承担「满高 + 内部滚动」
<div style={{ height: '100%', display: 'flex', flexDirection: 'column', gap: 16 }}>
  <PageHeader />                                {/* shrink-0 */}
  <FilterBar />                                 {/* shrink-0 */}
  <ToolbarBar />                                {/* shrink-0 */}
  <Card style={{ flex: 1, minHeight: 0 }}>      {/* 可伸缩 */}
    <Table scroll={{ y: 'calc(100% - 56px)' }} /> {/* 只在卡片内部滚 */}
  </Card>
</div>
```

四条约束：

1. **禁止魔法高度**：不允许 `height: 520`、`maxHeight: 52vh` 决定一屏结构；
2. **固定区 `flex-shrink: 0`**（标题、筛选、工具栏）；
3. **伸缩区 `flex: 1; min-height: 0`**（表格、图表）；
4. **页面本身不出现第二条滚动条**——`html/body` 在后台布局内不滚动。

> 现状问题：`AdminLayout` 用 `position: fixed` + `height: 100vh` + Content `margin: 24`，滚动发生在 Content 外层，导致长列表时筛选条会被滚走。改造点是给 `Content` 内层一个 `height: 100%` 容器并接管滚动。

## 四、页面模板

### 4.1 列表页（覆盖 20+ 页）

```
┌ PageHeader ────────────────────────────────────────────┐
│ 标题 + 一句话说明                        [次要操作][主操作] │
├ FilterBar ─────────────────────────────────────────────┤
│ [搜索框] [下拉筛选] [日期范围] [重置][查询]              │
├ ToolbarBar ────────────────────────────────────────────┤
│ 已选 N 项：批量发布 | 批量删除        共 128 条 · 刷新   │
├ Table ─────────────────────────────────────────────────┤
│ 名称(弹性) 分类(120) 状态(100) 时间(190) 操作(180 固定右) │
└────────────────────────────────────────────────────────┘
```

- 换筛选**必须清空已选**（防"删掉看不见的行"，现有代码已实现，改造时保留）；
- 空态：隐藏分页 + 显示插画/文案 + 主操作按钮；
- 批量操作条只在有选中时出现，不占常驻高度。

### 4.2 编辑页（覆盖 15+ 页）

```
┌ 顶部固定 56：返回 | 标题 | 状态标签 ……… 预览 | 保存 ┐
├──────────────────────────┬─────────────────────────┤
│ 主区（弹性，可滚动）      │ 侧区 320 固定            │
│ 标题 / 正文 / 章节        │ 分类 / 状态 / SEO / 封面 │
└──────────────────────────┴─────────────────────────┘
```

- 侧区在 `<1280px` 时移入折叠面板，**不做 splitter**；
- 离开前未保存提示（`useUnsavedChangesGuard` 已有）；
- 保存按钮 loading，禁止整页遮罩。

### 4.3 设置页（26 组 137 项）

```
┌ 左分类 200 ┬ 分组标题 + 保存 ─────────────┐
│ 基础        │ 字段（label 右对齐，统一宽度） │
│ 内容与检索  │ 说明文字走 colorTextTertiary  │
│ 媒体        │ [测试连接]                   │
└────────────┴──────────────────────────────┘
```

- 未保存分组在左侧栏打小圆点（现有 `dirtyGroups` 已有）；
- 密钥类字段：默认掩码，聚焦后可改，**回车不提交**。

### 4.4 看板（已实现，仅调密度）

- 指标卡 4 列（`<1280px` 2 列），卡内 padding 16；
- 图表必须给容器**可测量高度**（`minHeight: 280`），否则 ECharts 初始化空白；
- 系统状态卡用状态点 + 文本，不用进度条。

## 六、状态与语义

| 语义 | 颜色 | 用于 |
|------|------|------|
| 主操作 | Primary | 新增、保存、查询、运行中 |
| 成功 | `#16A34A` | 已发布、成功、已连接、正常 |
| 警告 | `#D97706` | 待处理、超时、额度将尽 |
| 危险 | `#CF1322` | 删除、停用、强制下线（**仅破坏性**） |
| 信息/中性 | 灰 | 草稿、已取消、未执行 |

规则：

- **一个区域只允许一个实心主按钮**，其余用默认/文字按钮；
- 状态标签高度 26、字号 12、圆角 6；
- 破坏性按钮默认透明 + 危险色文字 + 浅红描边，hover 淡红底，**禁止灰底**；
- 定时任务四态（正常/上次失败/未按时执行/从未执行）必须用四种不同语义色，不可复用。

## 八、为什么不用 Tailwind

参考项目用 `Tailwind 4 + SCSS + Element Plus 变量` 三套并存。我们不引入 Tailwind：

1. AntD 6 已有完整的 token 体系（`theme.token` / `components`），能覆盖 90% 需求；
2. 引入 Tailwind 会出现"哪个类优先"的持续争论，新人成本高；
3. 关键少数场景（一屏布局链）用 3 个 CSS 变量即可：
   ```css
   :root {
     --app-gap: 16px;
     --app-radius: 12px;
     --app-header-h: 56px;
   }
   ```
4. 真要上原子类，也是在 token 稳定之后的事，不是现在。

## 十、验收清单

改完任何页面前跑一遍：

- [ ] 无魔法高度；一屏布局只在内部滚动
- [ ] 卡片间距 16 / 圆角 12 / 页面内边距 16
- [ ] 表格：行高 40 / 表头 44 / 时间列 190 / 操作列 180 固定右
- [ ] 一个区域只有一个实心主按钮
- [ ] 破坏性按钮走危险色，无灰底
- [ ] 空态隐藏分页，首屏用骨架屏
- [ ] 次要文字对比度 ≥ 4.5:1（用 `#595959`，不许回落 `rgba(0,0,0,.45)`）
- [ ] 换筛选清空已选
- [ ] 弹窗底部按钮可见，内容区独立滚动
- [ ] 截图验证 1280 / 1440 / 1920 三档
- [ ] `npm run build && npm test` 通过
