## 三、与其他文档的关系

```
docs/
├─ 01-产品 / 02-架构 / 03-开发 / 04-运维 / 05-测试   # 内部工程文档（更细，含运维手册）
├─ 06-开源
│  ├─ 开源就绪评估与功能路线.md        # 开源决策与路线
│  ├─ 仅开源后台管理端-切割方案.md      # 模块切割与里程碑
│  └─ 底座对标与融合方案.md            # 对标五个开源项目的融合清单
└─ 07-开源文档/                        # ← 本目录：对外交付的五份规范文档
```

**分工**：`06-开源` 记录**怎么开源**（决策、切割、改造）；`07-开源文档` 是**开源后给用户看的**说明书。内部运维细节（备份、监控、故障排查）留在 `04-运维`，不进本文档集——对外文档只承诺能力，不承诺运维细节。

## 四、维护约定

1. **数字必须可核对**：文中所有规模数字（40 张表、268 个操作、63 权限码、26 组设置、9 个任务、155 个测试文件）来自代码扫描，改代码时同步更新；
2. **现状与规划分开写**：已实现用「✅」或直述，未实现必须标注「规划」并给出编号（如 P-03），不允许把规划写成现状；
3. **限制必须明说**：`03-技术文档 §十 已知限制` 是承诺清单，删掉一条等于对外撒谎；
4. **新增模块时**同步更新三处：`01-功能文档 §二 功能地图`、`04-架构文档 §五 数据模型`、`05-开发文档 §五 检查清单`；
5. 文档链接由 `scripts/check_docs_links.py` 守卫，改文件名必须同步改索引。
