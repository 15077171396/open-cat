## 一、背景与问题

### 1.1 要解决的问题

建站者的真实困境不是"没有 CMS"，而是**三件事凑不齐**：

1. 开源 CMS（WordPress / Strapi / Ghost）**权限粗、审计弱**——多人协作时无法回答"是谁把这个价格改了"；
2. 国内后台框架（RuoYi / JeecgBoot）**领域绑定深**——想改成内容站，得先拆掉半个脚手架；
3. AI 时代的内容生产**缺工具链**——编辑器是哑的，配图靠手找，审核靠人肉。

### 1.2 我们的答案

一个**内容中台**：后台负责「人 + 内容 + 权限 + 审计 + AI 辅助」，前台由使用者用开放 API 自建。

## 二、目标用户与场景

| 角色 | 画像 | 核心诉求 | 典型动作 |
|------|------|---------|---------|
| **独立站长**（P0） | 1 人运营内容站，懂技术 | 10 分钟跑起来，一个人也能管住几十个用户与几百篇内容 | 建栏目 → 写教程 → 配 SEO → 看数据 |
| **小团队运营**（P1） | 3～8 人，编辑 + 审核 + 客服分工 | 权限要细，谁删了内容要能查到 | 分配角色 → 编辑写稿 → 审核发布 → 处理举报 |
| **二次开发者**（P1） | 接单/自建产品 | 加自己的内容类型不改核心，接口稳定 | 读架构文档 → 加模块 → 配权限 → 前台对接 API |
| **评估者**（P0） | 刷 GitHub 的开发者 | 30 秒判断值不值得 star | 看截图 → 看 README 对比表 → clone 跑 demo |

## 三、产品目标与非目标

### 3.1 目标（V1）

| # | 目标 | 度量 |
|---|------|------|
| G1 | 陌生机器 10 分钟内跑通并登录后台 | `git clone` → 登录 ≤ 3 条命令 |
| G2 | 后台 100% 操作可归因到人 | 写操作审计覆盖率 100%（测试守卫） |
| G3 | 权限可配到按钮级且不可越权 | 越权访问返回 403，前端无入口 |
| G4 | 不配任何第三方 Key 也能完整体验 | 存储/邮件/AI/支付均有降级实现 |
| G5 | 二次开发者可在不改核心的前提下加内容类型 | 新模块只动 `module_registry` + 新目录 |

### 3.2 非目标（V1 明确不做）

- 多租户、SaaS 计费、组织级数据隔离
- 低代码表单设计器、在线建表、流程引擎
- 站内资金操作（退款/改单）
- 国际化（V1 仅中文，V2 抽骨架）
- 移动端管理界面（仅做审核/客服三页响应式）

## 四、用户故事

### Epic 1｜部署与初始化（P0）

| ID | 故事 | 验收标准 |
|----|------|---------|
| US-1.1 | 作为站长，我想用一条命令启动服务，以便 10 分钟内看到后台 | `docker compose up -d` 后 ≤ 3 分钟可访问 `/admin`；无需手改 env 即可登录 |
| US-1.2 | 作为站长，我想在网页上完成初始化，以便不碰配置文件 | 首次访问跳 `/admin/setup`：创建管理员、选存储、测邮件、生成 SECRET_KEY；完成后该路径永久关闭 |
| US-1.3 | 作为站长，我想确认环境是否健康 | 体检页展示 DB / Redis / 存储 / 邮件 / AI / 调度 六项连通性，失败给修复指引 |

### Epic 2｜内容生产（P0）

| ID | 故事 | 验收标准 |
|----|------|---------|
| US-2.1 | 作为编辑，我想写多章节教程 | 章节树支持增删改与拖拽排序；正文富文本支持表格/代码块/图片；草稿可预览 |
| US-2.2 | 作为编辑，我想在编辑器里让 AI 改写与配图 | 选中文本弹 AI 气泡；改写结果可 diff 对比后插入；插图走图库或 AI 生成；超配额给明确提示 |
| US-2.3 | 作为编辑，我想批量发布/撤下/删除 | 列表支持多选；换筛选自动清空选择；操作前二次确认并显示影响条数 |
| US-2.4 | 作为编辑，我误删了内容想找回 | 回收站视图可恢复；恢复后回到原状态而非草稿 |

| ID | 故事 | 验收标准 |
|----|------|---------|

| US-3.3 | 作为管理员，我想管住评论 | 可删除与恢复；**不提供编辑**（防篡改用户发言） |

### Epic 4｜用户与权限（P0）

| ID | 故事 | 验收标准 |
|----|------|---------|
| US-4.1 | 作为超管，我想按岗位分配权限 | 角色可勾选 63 个权限码（菜单树形态）；保存后目标用户下次请求即生效 |
| US-4.2 | 作为超管，我想知道谁做了什么 | 审计列表可按模块/操作人/时间/结果筛选；详情含请求摘要 |

### Epic 5｜运营与商业化（P1）

| ID | 故事 | 验收标准 |
|----|------|---------|

### Epic 6｜系统配置（P0）

| ID | 故事 | 验收标准 |
|----|------|---------|

## 六、非功能需求

### 6.1 性能

| 指标 | 目标 | 当前 |
|------|------|------|
| 列表接口 P95 | < 200ms（10 万行量级） | 未测（无基线） |
| 详情接口 P95 | < 150ms | 未测 |
| 写接口 P95 | < 300ms | 未测 |
| 列表接口 SQL 条数 | ≤ 3（防 N+1） | 未约束 |
| 后台首屏 LCP | < 1.5s | 未测 |
| 入口 JS（gzip） | < 200KB | 未测 |

> ⚠️ NFR-1 是首发前的硬门槛：**没有基线就没有"性能达标"这个结论**。

### 6.2 安全

| 类别 | 要求 | 状态 |
|------|------|------|
| 密码 | bcrypt，拒绝 > 72 字节，校验不阻塞事件循环 | ✅ |
| 时序攻击 | 账号不存在时对 dummy hash 做真实校验 | ✅ |
| 令牌 | 访问令牌内存/会话存储，refresh 仅 httpOnly cookie | ✅ |
| 密钥存储 | 第三方密钥加密落库，掩码回显 | ✅ |
| 限流 | 敏感端点 Redis 故障时 fail-closed | ✅ |
| 审计 | 写操作 100% 留痕且测试守卫 | ✅ |
| 会话管理 | 强制下线 / 改权即时生效 | ❌ 规划 P-03 |
| 幂等 | 写操作幂等键 | ❌ 规划 P-04 |
| 上传 | magic bytes 校验 + 图片重编码 | ⚠️ 部分 |
| SSRF | 出站请求域名白名单 | ⚠️ 部分 |

### 6.3 兼容与运行环境

- Python 3.11+；Node 22（构建）；MySQL 8.0+；Redis 7+；
- 浏览器：Chrome / Edge 最近两个大版本；
- 部署：Docker Compose（推荐）/ 裸机 uvicorn + nginx；
- 单实例部署（调度器为进程内实现）。

### 6.4 可维护性

- 后端测试 141 个文件 / 1800+ 测试函数，**全程离线**（不需 MySQL/Redis）；
- 前端 36 个测试文件（vitest + Testing Library）；
- CI 四 job：后端测试、迁移往返校验、前端构建 + 测试、镜像构建；
- 三个零依赖静态自检：CI 版本一致性、文档链接、环境变量一致性。

## 七、V1 开源范围

| 交付 | 内容 |
|------|------|
| ✅ 包含 | 后端（全部 admin 相关 API + 内容只读 API + 最小 C 端认证 API）、管理后台前端、部署脚本、种子数据、文档集 |
| ❌ 不含 | PC 用户端、微信小程序、SEO 预渲染服务、统计服务、看门狗脚本 |

**首发验收（Definition of Done）**

1. 陌生机器 `git clone` → `docker compose up -d` → 浏览器登录后台，全程不编辑配置文件；
2. 所有列表页有演示数据，所有按钮可点且不报错；
3. 关掉任意一个可选模块，服务仍能正常启动；
4. `gitleaks` 全仓零命中；
5. README 含 6 张截图、对比表、10 分钟快速开始。
