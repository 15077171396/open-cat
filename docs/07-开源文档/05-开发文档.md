## 一、环境准备

| 依赖 | 版本 | 备注 |
|------|------|------|
| Python | 3.11+ | 生产镜像 3.11 |
| Node.js | **22** | 不要更低：CI 与生产镜像统一，构建脚本依赖 22.6+ |
| MySQL | 8.0+ | 需要 `ngram` 全文索引 |
| Redis | 7+ | 限流/缓存/调度 |

```bash
git clone <repo> && cd <repo>
cp backend/.env.example backend/.env      # 填入 DB / Redis / SECRET_KEY
```

> ⚠️ `SECRET_KEY` 同时用于 JWT 签名与密钥加密派生。**换掉它会导致已加密的第三方密钥解不开**（系统会回退 env 并记日志，不会崩，但需重新在后台填一遍）。

## 二、启动

### 2.1 后端

```bash
cd backend
python -m venv venv
venv/Scripts/activate            # Windows
# source venv/bin/activate       # macOS / Linux

pip install -r requirements.txt
mysql -u root -p < init_db.sql
alembic upgrade head

```

### 2.2 前端

```bash
cd admin-frontend
npm install
npm run dev        # http://localhost:5174/admin/
```

> **后端与前端必须分终端运行**：Windows 下 uvicorn 的 reload 会波及其他同终端进程。

填账号口令即可；也可以继续用 `python seed_data.py` 建号（口令取 `ADMIN_PASSWORD`）。
两条路径等价，向导只是省掉了「去日志里抄随机口令」这一步。

想看演示数据（截图、演示站、验收界面）：


## 三、目录约定

| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| `backend/app/api/` | 路由、请求模型、依赖声明 | SQL、业务规则 |
| `backend/app/services/` | 业务规则、事务、缓存失效、审计 | `Request` 对象 |
| `backend/app/models/` | ORM 字段、关系、索引 | 跨表业务逻辑 |
| `backend/app/schemas/` | Pydantic 模型 | 数据库访问 |
| `backend/app/core/` | 横切基建（异常、鉴权、加密、限流） | 业务代码 |
| `backend/tests/` | pytest 用例（`test_<域>_<行为>.py`） | 需要外网的用例 |
| `admin-frontend/src/pages/<模块>/` | `List.tsx` / `Edit.tsx` / `index.tsx` | 公共组件 |
| `admin-frontend/src/components/` | 可复用组件（43 个） | 单页面专用逻辑 |
| `admin-frontend/src/hooks/` | 数据编排 hooks | UI 渲染 |

**文件命名**：后端 `snake_case`；前端组件 `PascalCase.tsx`，hook `useXxx.ts`，工具 `camelCase.ts`。

## 四、编码规范

### 4.1 后端

- 行宽 100，`ruff check` 必须通过（`ruff.toml` 已配）；
- **全异步**：`api/` 与 `services/` 内不得出现同步 DB 调用；
- 路由函数只做三件事：校验参数、调 service、包响应信封；
- service 返回 **ORM 对象或数据类型**，不返回 `dict` 拼装（序列化交给 `response_model`）；
- 列表查询必须显式 `selectinload` / `joinedload`，禁止在循环里触发懒加载；
- 所有写操作必须写审计（见 §五.3）；
- 注释写**为什么**，不写**是什么**——现有代码里大量 `⚠️` 注释都是踩坑记录，改动前先读。

### 4.2 前端

- `eslint src` 必须通过；`tsc -b` 零错误（构建门禁）；
- 组件默认导出、文件同名；props 显式 interface；
- 请求统一走 `apiGet/apiPost/...`（自动解包信封），不直接用 axios；
- 权限判断用 `<RequirePerm>` 或 `hasPerm()`，不手写角色名判断；
- 状态：全局用 Zustand，页面内用 `useState`；列表数据用 `useCrudList`；
- 样式：优先 antd token（`theme.ts`），不硬编码颜色。

## 五、新增一个业务模块（核心流程）

以「新增 `webinars`（线上课）模块」为例，共 8 步。**漏一步就会出现"菜单有入口但 403"或"审计缺失导致 CI 红"。**

### 5.0 先跑脚手架（省掉四份样板文件）

```bash
cd backend
python scripts/new_module.py webinar --label 线上课 --dry-run   # 先看要生成什么
python scripts/new_module.py webinar --label 线上课             # 落盘
```

生成 5 个文件：model / schema / admin service / admin router / 前端列表页。
其中已经按仓库约定写好**审计留痕、事务边界（commit 只在 service）、`require_admin` 权限依赖、
PageHeader + ListToolbar + DataTable 骨架**，`tests/test_new_module_scaffold.py` 会守着这些约定。

生成器**不猜业务、也不自动改注册表**：权限码 / 菜单 / 路由规则表 / 模块注册表 / 前端路由
这 5–8 处登记会在终端打印成清单（带锚点），由人确认后再改 —— 自动改 6 个注册表出错时更难排查，
而漏登记会被下面几节的守卫当场抓住。之后按 5.1–5.8 继续。

### 5.1 数据层

```python
# backend/app/models/webinar.py
class Webinar(Base):
    __tablename__ = "webinars"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    status: Mapped[str] = mapped_column(String(20), default="draft")
    deleted_at: Mapped[datetime | None] = mapped_column(default=None)
```

```bash
alembic revision --autogenerate -m "add webinars"
alembic upgrade head
```

### 5.2 权限码（**必做**）

```python
# backend/app/services/rbac_catalog.py
PermissionDef("webinar:view",   "线上课查看", "menu",   "webinar", "线上课", 130),
PermissionDef("webinar:create", "新增线上课", "button", "webinar", "线上课", 131),
PermissionDef("webinar:edit",   "编辑线上课", "button", "webinar", "线上课", 132),
PermissionDef("webinar:delete", "删除线上课", "button", "webinar", "线上课", 133),
```

> `code.split(":")[0]` 决定它归哪个模块，内置角色的权限集合按前缀自动派生。登记后内置角色**自动获得**对应权限，无需改 `SYSTEM_ROLES`。

### 5.3 服务层 + 审计（**必做**）

```python
# backend/app/services/admin_webinar_service.py
from app.services.admin_audit_service import record_admin_action

async def delete_webinar(db, webinar_id: int, actor: User) -> None:
    webinar = await _get_or_404(db, webinar_id)
    webinar.deleted_at = utcnow()
    record_admin_action(          # ⚠️ 只 add，不 commit
        db, actor, "delete",
        target_type="webinar", target_id=webinar_id,
        summary=f"删除线上课 {webinar.title}",
    )
    await db.commit()             # 审计与业务同事务提交
    await purge_content_cache("webinar", webinar_id)
```

两个易错点：

- `record_admin_action` **不 commit**，由调用方在同一事务提交，保证「业务成功但审计丢失」不可能发生；
- `action` 必须在 `AUDIT_ACTIONS` 登记，否则后台筛选下拉里选不到它（系统仍会记录并打 warning，不让业务失败）。

审计缺失会被 `tests/test_admin_audit_coverage.py` 抓到，CI 直接红。

### 5.4 路由 + 路由规则表（**必做，漏了直接 403**）

```python
# backend/app/api/admin_webinars.py
from app.api._admin_shared import router      # 统一 /admin 前缀，已挂全局权限依赖
from app.core.permissions import require_admin

@router.get("/webinars", response_model=ApiResponse[PageResult[WebinarItem]])
async def list_webinars(..., _: User = Depends(require_admin("webinar:view"))): ...

@router.delete("/webinars/{wid}", response_model=ApiResponse[ActionAck])
async def delete_webinar(wid: int, ..., actor: User = Depends(require_admin("webinar:delete"))): ...
```

```python
# backend/app/core/rbac.py —— ⚠️ 不登记 = 一律 403（fail-closed）
_RULES: list[tuple[str, str, list[str]]] = [
    ...
    ("GET",    "/api/v1/admin/webinars",     ["webinar:view"]),
    ("POST",   "/api/v1/admin/webinars",     ["webinar:create"]),
    ("PUT",    "/api/v1/admin/webinars/{id}", ["webinar:edit"]),
    ("DELETE", "/api/v1/admin/webinars/{id}", ["webinar:delete"]),
]
```

> 这是本项目最容易被漏掉的一步：`_admin_shared.router` 挂了全局依赖 `check_route_permission`，**未匹配规则的请求一律 403**。好处是即使漏写 `require_admin` 也不会权限裸奔。

```python
# backend/app/api/admin.py —— 一行 import 即完成注册
from app.api import admin_webinars  # noqa: F401
```

`admin.py` 的机制是「import 即执行各模块的 `@router` 装饰器完成注册」，不要在其中写其他逻辑。

### 5.5 菜单

```python
# backend/app/services/admin_menu.py
MenuItem("/webinars", "线上课", "play-circle", perm="webinar:view"),
```

放在对应 `MenuGroup` 的 `items` 里。**菜单与权限码必须对上**，`test_admin_menu.py` 会校验。

### 5.6 前端页面

```
admin-frontend/src/pages/Webinars/
├─ List.tsx     # 用 useCrudList + ListPageHeader + Table
└─ Edit.tsx     # 用 EditPageLayout + 表单
```

### 5.7 前端路由

在路由表里加一条即可，**不要**去改 `App.tsx`：

```tsx
// admin-frontend/src/routes/adminRoutes.tsx
const WebinarsList = lazy(() => import('../pages/Webinars/List'))

export const ADMIN_ROUTES: AdminRouteDef[] = [
  // ...
  { path: '/webinars', element: <WebinarsList />, perm: 'webinar:view' },
]
```

`App.tsx` 只负责「登录页 / 安装向导 / 兜底路由 + 渲染整张表」，业务页面一律不进它。

> **为什么要这样**：路径、组件、权限码写在一处，`backend/tests/test_admin_routes.py`
> 才能跨语言校验三件事——权限码真实存在、每条路由都挂了守卫、路由与菜单用的是同一组权限码。
> 这三类错误以前都只表现为「菜单点进去 403」或「有权限但没入口」，没有任何测试能发现。

### 5.8 测试

```python

async def test_delete_writes_audit(fake_db, ...): ...
```

- [ ] `models` + 迁移

## 六、常见二次开发任务

### 6.1 新增一个系统设置项

```python
# backend/app/services/setting_definitions.py
SettingDefinition(
    key="webinar_reminder_minutes",
    group="business",                 # 必须已在 SETTING_GROUPS 登记
    group_label="业务规则",           # 必须与登记一致，否则导入期直接报错
    label="开播提醒提前分钟数",
    type="int", default=30,
    description="0 表示不提醒",
)
```

前端无需改动——设置页按分组自动渲染（`SettingsEditor` 配置驱动）。若需自定义控件，在 `components/settings/SettingField.tsx` 扩展类型。

### 6.2 新增一个定时任务

```python
# 1) scheduler/tasks.py
async def send_webinar_reminders() -> str: ...

JOB_FUNCS = {..., "send_webinar_reminders": send_webinar_reminders}

# 2) services/scheduled_job_service.py
JobSpec(id="send_webinar_reminders", label="开播提醒",
        category=CATEGORY_USER, desc="...", kind="interval", interval_minutes=5,
        stale_seconds=900)
```

两处 id 必须一致，`tests/test_scheduled_jobs.py` 读源码双向比对。**任务体永远写代码，后台只能改周期**。

### 6.3 接入一个新的 AI 供应商

在 `app/services/ai/` 下新增适配器，实现既有接口（`chat` / `chat_stream` / 可选 `image`），在供应商注册处登记即可。密钥统一走 `core/crypto.py` 加密落库，不要在业务代码里直接读 env。

### 6.4 新增一个存储驱动（开源版）

实现 `StorageProvider` 接口：`put` / `get` / `delete` / `sign_url`。默认 `local` 落卷，`s3` 兼容 MinIO/R2/OSS，`cos` 保留现有实现。

## 七、测试规范

| 类型 | 位置 | 要求 |
|------|------|------|
| 接口测试 | `tests/test_admin_*.py` | 覆盖成功 + 权限拒绝 + 参数非法 三条路径 |

## 九、调试与排错

| 现象 | 原因 | 处理 |
|------|------|------|
| 登录后立刻 401 | `SECRET_KEY` 变更导致旧令牌失效 | 重新登录；不要在生产随意换 SECRET_KEY |
| 菜单空白 | `/admin/menus` 请求失败，sessionStorage 缓存版本不匹配 | 清 sessionStorage；看 network |
| 上传报错 | COS 未配置或密钥解密失败（SECRET_KEY 换过） | 后台重填存储配置；看日志 `decrypt` |
| 后台某设置不显示 | 定义用了未登记的 `group` | 启动会直接失败并指出组名 |
| 定时任务"从未执行" | 调度器未启动或 `job_id` 拼错 | 查 `ops:jobs:applied` 心跳；跑 `test_scheduled_jobs.py` |
| 定时任务不按新周期跑 | 配置指纹未变却重复 `add_job` | 不要动对齐逻辑里的"未变不重排"分支 |
| 限流误伤 | 窗口/配额配置过低 | 后台「访问限流」组调高；健康检查与 CORS 预检不计入 |
| Redis 挂后登录失败 | 敏感端点 fail-closed（有意设计） | 恢复 Redis；这是安全取舍不是 bug |
| 列表出现已删数据 | 查询漏了 `deleted_at IS NULL` | 补条件并加测试 |
| 前端构建失败但 dev 正常 | `tsc -b` 严格检查 | 修类型，不要 `// @ts-ignore` |

## 十、发布流程

```bash
# 1. 全量自检（§2.3）
# 2. 版本与变更
#    - 更新版本号
#    - CHANGELOG 记录（Breaking Change 单列）
# 3. 迁移检查
backend/venv/Scripts/python.exe scripts/verify_migrations.py
# 4. 构建镜像
docker compose build app nginx
# 5. 部署
./deploy.sh up
# 6. 上线后验证
curl -s localhost/api/v1/health/deep | jq
```

**发版红线**

- 迁移必须可回滚（`downgrade` 不能是空实现）；
- 破坏性配置变更必须在 CHANGELOG 标注并提供迁移脚本；
- 新增必需环境变量必须同步 `.env.example`，否则 `check_env_consistency.py` 会失败。
