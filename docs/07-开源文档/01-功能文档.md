## 一、一句话定位

一个自带 **按钮级 RBAC、全量操作审计、UGC 审核、AI 写作** 的内容运营后台：你用它管内容与用户，用它开放的 API 渲染自己的站点。

**不是**：通用低代码平台、无头 CMS 的前端套件、开箱即用的 SaaS。

## 二、首次部署：安装向导

全新的库打开 `/admin` 会被送到 **`/admin/setup`**，填账号 + 口令即可创建第一个管理员，
成功后该页自动关闭（接口返回 409）。

| 行为 | 说明 |
|------|------|
| 触发条件 | 库里没有任何 `role=admin` 且未软删的账号 |
| 收集字段 | 账号、口令（≥8 位）、昵称（可选）——**只建号，不收配置** |
| 角色绑定 | 自动绑定 `super_admin`；RBAC 表未就绪时降级为「去后台手动分配」 |
| 关闭时机 | 一旦存在管理员，`/setup/init` 永久返回 409 |
| 其他配置 | 存储 / 邮件 / AI / 支付一律留给「系统设置」，那里有掩码与独立权限码 |

> 设计上的取舍：向导**不**帮你配 SMTP 或存储。把配置塞进首屏会让它变成第二个
> 不受审计的配置入口，而「先能登录，再慢慢配」才是真实使用顺序。

想先看看「有数据的样子」，再跑 `python seed_demo.py`：灌入教程/百科/资源/工具/扩展/
评论/反馈/公告/积分流水，并现场生成封面与头像写入存储（local 与 cos 驱动都适用）。
脚本幂等（以 `【示例】` 前缀识别），重复执行会跳过。

## 三、功能地图

侧边栏 5 个分组、**32 个菜单入口**，全部由后端 `admin_menu.py` 下发并按权限过滤——**没有权限的入口不会出现**，直接输 URL 会被 `RequirePerm` 拦成 403。

### 3.1 概览

| 页面 | 能力 | 关键细节 |
|------|------|---------|
| 数据看板 | 核心指标卡、注册/下载趋势、转化漏斗、AI 用量、内容归因、系统状态 | 指标口径与聚合 SQL 在 `stats_service` / `funnel_service`；系统状态含 MySQL/Redis 延迟、任务心跳 |
| 访问统计 | 外链跳转独立统计服务（Umami） | 未配置时不显示入口 |

### 3.2 内容管理

| 页面 | 能力 | 关键规则 |
|------|------|---------|
| 教程管理 | 教程 CRUD、**章节树**（多级节点）、发布/撤下、批量发布/删除/恢复、回收站 | 正文走章节节点，`tutorials.content` 仅为兼容旧请求的备份字段 |
| 资源管理 | 资源 CRUD、网盘链接（多行）、下载计数、回收站 | 网盘链接独立子表 `resource_netdisk_links` |
| 知识百科 | 树形节点 CRUD、排序移动 | 与教程的区别：单节点内容，无章节层级 |
| 在线工具 | 工具 CRUD、使用量统计 | 使用日志 `tool_usage_logs` 用于排行 |
| 扩展管理 | 扩展 CRUD、来源标注 | 支持 GitHub README 抓取作为描述来源 |
| 分类管理 | 分类 CRUD、排序、启用开关 | 内容表单的分类下拉数据源 |
| 素材库 | 上传/图库导入/AI 图统一浏览与复用、批量下载 | 素材 `image_assets`，编辑器内可直接引用 |

> 五种内容类型（教程/资源/百科/工具/扩展）共用一套「列表-编辑-预览-发布」交互范式，但数据模型各自独立。

### 3.3 运营管理

| 页面 | 能力 | 关键规则 |
|------|------|---------|
| 公告管理 | 公告 CRUD、定时发布/撤下、批量操作 | 状态机：草稿 → 已发布 → 已撤下 |
| 充值套餐 | 套餐 CRUD（价格/额度/排序/上下架） | **改价直接影响收款**，按高危按钮权限管理 |
| 支付订单 | 订单查询（只读） | **刻意不提供改状态/退款**：退款走商户后台，避免站内出现第二套资金操作 |
| 内容审核 | Tab1 机审留痕复核；Tab2 人工举报处理 | 机审记录 `content_moderation_logs`，举报 `content_reports` |
| 内容评论 | 评论列表、筛选、删除、恢复 | 不提供编辑（改内容等于篡改用户发言） |
| 用户反馈 | 反馈查看、状态处理 | — |
| 消息通知 | 向全体/指定用户发系统通知 | 只有 view/send，无编辑与撤回（撤回等于删用户数据） |
| 搜索词分析 | 站点搜索词排行、零结果词 | 零结果词 = 内容缺口，是选题来源 |

### 3.4 用户与权限

| 页面 | 能力 | 关键规则 |
|------|------|---------|
| 用户管理 | 用户 CRUD、禁用/启用、软删除、**恢复已注销用户**、调整积分、分配角色 | `user:restore` 与 `user:delete` 刻意拆成两个权限码：能删 ≠ 能放回 |
| 实名审核 | 审核列表、通过/驳回 | 需 `auth_request:review` |
| 积分流水 | 流水查询（只读） | 记录 `point_transactions` |
| 积分兑换码 | 生成、批量导出、作废 | 兑换记录 `redemption_records` 与码分离 |
| 角色管理 | 角色 CRUD、权限树勾选、成员管理 | 内置角色不可删除 |
| 部门管理 | 树形部门 CRUD | 为后续数据权限预留 |

### 3.5 系统

| 页面 | 能力 |
|------|------|
| 系统设置 | 26 组 / 137 项配置，分类左侧栏导航，支持脏标记与保存前校验 |
| 登录管理 | 手机号/微信/小程序登录开关、微信凭据、短信通道（腾讯云/阿里云） |
| 法律文档 | 隐私政策 / 用户协议 / 免责声明 |
| 支付与渠道 | 支付总开关、模拟支付、微信支付、支付宝凭据 |
| 邮件通知 | SMTP 配置 + 测试发信 |
| 模型管理 | AI 供应商凭据、模型列表、单模型单价、全站成本护栏 |
| AI 写作 | 编辑器 AI 改写/续写/插图的提示词与参数 |
| 定时任务 | 8 个任务的周期配置、立即执行、执行历史、超期告警 |
| 操作审计 | 全量写操作留痕，按模块/操作人/时间检索 |
| 个人中心 | 资料、改密、2FA（TOTP）、我的权限 |

## 四、角色与权限

### 4.1 权限模型

- 权限码格式 `{module}:{action}`，共 **80 个**，两级：`menu`（菜单/查看）、`button`（写操作）；
- 权限码声明在 `rbac_catalog.py`，**同一份声明**派生：侧边栏菜单、前端路由守卫、后端依赖注入、内置角色；
- 自定义角色可从 80 个权限码中任选组合，支持菜单树勾选。

### 4.2 内置角色

| 角色 | 权限范围 | 说明 |
|------|---------|------|
| 超级管理员 `super_admin` | 全部 80 个 | 校验时直接绕过权限检查（逃逸通道），不可删除 |
| 内容管理员 `content_admin` | 内容 + 审核 + 评论 + 看板 | 不含用户管理与系统设置 |
| 只读管理员 `viewer` | 所有 `:view` 后缀 | **刻意排除 `audit:view`**：审计日志会暴露正在被调查的对象 |

### 4.3 权限的五个落点（同源 + 默认拒绝）

```
rbac_catalog.py（唯一声明，80 个权限码）
   ├─→ 后端依赖 require_admin(perm)      → 接口 403
   ├─→ 路由规则表 core/rbac.py           → 未登记即 403（fail-closed）
   ├─→ admin_menu.py 菜单下发            → 侧边栏隐藏
   ├─→ 前端 <RequirePerm>                → 直接输 URL 也 403
   └─→ 前端按钮 disabled/hidden          → 不可点击
```

其中「路由规则表」是最后一道兜底：**新接口没登记规则就一律 403**，而不是默认放行。所以漏写权限判断也不会造成越权泄漏。

## 五、跨模块业务规则

| 规则 | 行为 |
|------|------|
| **发布状态机** | 草稿 → 已发布 → 已撤下；批量发布/撤下需对应写权限 |
| **软删除与回收站** | 内容类资源删除即软删（`deleted_at`），列表可切「回收站」视图恢复；用户软删后可 `restore` |
| **审计强制** | 所有写操作落 `admin_audit_logs`；缺失即测试失败（`test_admin_audit_coverage.py`） |
| **幂等提示** | 前端防抖 + 后端限流；重复提交在数据层仍有风险（幂等键为规划项） |
| **AI 配额** | 单用户日限 + 全站日/月护栏 + 超时预算，三级可配；超限返回明确错误而非静默失败 |
| **密钥展示** | 所有第三方密钥加密落库，管理端只回显掩码 `********`；提交掩码不会覆盖真值 |
| **敏感配置隔离** | 登录/支付/法务/邮件四类配置从「系统设置」抽出为独立页面与独立权限码 |

## 六、明确不支持的能力

写清楚边界比堆功能更能建立信任：

- ❌ 多租户 / SaaS 隔离（单实例单站点）
- ❌ 在线建表、低代码表单设计器、流程引擎
- ❌ 站内资金操作（退款、改单）—— 一律回商户后台
- ❌ 代码级插件机制（当前"扩展管理"是内容业务模块，不是插件系统）
- ❌ 国际化（界面仅简体中文）
- ❌ PostgreSQL / SQLite（依赖 MySQL 8 全文索引 `ngram`）
- ❌ 水平扩展（定时调度为单实例内存实现）

## 七、界面与交互约定

- **列表页统一**：筛选区 + 工具条（批量操作）+ 表格 + 分页；换筛选自动清空选择，避免"删掉看不见的行"；
- **编辑页统一**：`EditPageLayout` 提供标题栏/保存/返回/预览；离开前有未保存变更确认；
- **富文本**：Quill 2 + 自定义 blot（表格、代码块、图注），支持 Markdown 粘贴与目录面板，`?` 唤起快捷键帮助；
- **错误呈现**：接口失败统一 toast + 保留表单状态；路由级 `ErrorBoundary` 防整页白屏；
- **主题**：当前单套亮色 token（`theme.ts`），暗色为规划项。
