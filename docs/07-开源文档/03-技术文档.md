## 二、运行拓扑

### 2.1 开发环境

```
浏览器 :5174/admin
   │  Vite dev server（/api 反代 127.0.0.1:8000）
   ▼
uvicorn :8000 ──→ MySQL 8 ──→ Redis 7
```

### 2.2 生产环境（推荐形态）

```
              ┌──────── CDN / WAF（可选）────────┐
              ▼
        nginx :80/443
        ├─ /admin/*  → 静态文件（后台构建产物）
        ├─ /api/*    → app:8000
        └─ 安全头 / gzip / CSP（nginx 唯一负责）
              ▼
        app（gunicorn + uvicorn worker）
        ├─ MySQL 8（业务数据）
        └─ Redis 7（缓存 / 限流 / 调度）
```

> **CSP 只在 nginx 下发**：后端 `security_headers.py` 刻意不下发 CSP，避免两处策略冲突把前端功能掐死。

### 2.3 进程模型与单实例约束

- `app` 单实例部署：APScheduler 在进程内，多实例会重复执行任务；
- 若需水平扩展：调度器独立进程 + 分布式锁（未实现，README 需明确声明）。

## 三、关键技术决策

| # | 决策 | 理由 | 代价 |
|---|------|------|------|
| D1 | **全异步 ORM（SQLAlchemy 2 async）** | IO 密集后台，同步驱动在并发 100 时线程池打满 | 所有查询必须 `await`；同步场景（迁移/脚本）另用 pymysql |
| D2 | **权限码单一事实来源** | 四处（接口/菜单/路由/按钮）人工对齐必然漂移 | 新增模块必须登记权限码，否则测试失败——这是**有意**的摩擦 |
| D3 | **审计强制而非可选** | "事后补审计"永远补不全 | 写操作必须走统一入口；有测试守卫扫描缺失 |
| D4 | **第三方密钥加密落库** | 配置可视化 + 不落明文 | SECRET_KEY 轮换会导致解密失败 → 设计为「解密失败回退 env，不崩」 |
| D5 | **JWT 访问令牌 + httpOnly refresh cookie** | 兼顾无状态校验与 XSS 抗性 | 需处理并发刷新的令牌轮换（已用 promise 单飞） |
| D6 | **限流 Redis 固定窗口 + 敏感端点 fail-closed** | 实现简单、可解释 | Redis 故障时敏感端点拒绝服务（有意选择） |
| D7 | **调度器双通道（配置表 + 命令队列）** | 任务体在代码里（可审查），周期在库里（可运维） | 需处理"配置未变不重复 add_job"的重排陷阱 |
| D8 | **设置分组声明式定义 + 导入期校验** | 分组/标签不一致会在启动时报错，而非渲染空白 | 新增设置必须同时登记分组 |
| D9 | **软删除 + 回收站** | 内容误删可恢复 | 所有查询必须带 `deleted_at IS NULL`，漏一处就是数据泄漏 |
| D10 | **MySQL 专属（`ngram` 全文索引）** | 中文分词开箱可用 | 放弃多方言；README 明确声明 |

## 四、配置体系

### 4.1 两套配置，职责分明

| 层 | 载体 | 内容 | 生效方式 |
|----|------|------|---------|
| **启动配置** | 环境变量 / `.env` | 数据库、Redis、SECRET_KEY、端口、CORS、Sentry | 需重启 |
| **运行时配置** | `system_settings` 表 | 26 组 / 137 项：品牌、限流、上传、SEO、AI、支付、邮件、登录、法务 | 保存即生效（少量标注需重启） |

**注入方式**：编排用 `env_file: .env` 全量注入（模板里有 99 个键，但**只有 5 个必填**：
`SECRET_KEY` / `MYSQL_ROOT_PASSWORD` / `REDIS_PASSWORD` / `NGINX_PORT` / `SITE_BASE_URL`），
再叠加少量 `environment:` 覆盖容器内地址（`DB_HOST=mysql`、`REDIS_HOST=redis`）。
好处是往 `.env` 加一个键不必回头改 compose；`scripts/check_env_consistency.py` 会守住
「模板里的键必须被后端认识」与「代码用到的配置必须可注入」两条。

### 4.2 密钥类配置的三层保护

```
用户输入明文
   → core/crypto.py encrypt_secret()  （PBKDF2 派生 + Fernet，密文带 enc:v2: 前缀）
   → 落库 system_settings.value
   → 读取时 decrypt_secret()；管理端回显 mask_secret() → ********
   → 前端误提交掩码时，looks_like_mask() 识别为「未修改」，不覆盖真值
```

版本化前缀 `enc:v1:` / `enc:v2:` 保证历史密文可读、可零破坏迁移。

### 4.3 设置分组（26 组）

`basic` `business` `ai` `ai_writing` `moderation` `upload` `image_search` `ratelimit` `search` `seo` `fetch` `storage` `auth_phone` `auth_wechat` `miniapp` `auth_sms` `payment_general` `payment_wechat` `payment_alipay` `mail` `hero` `default` `qrcode` `social` `invite` `legal`

> 声明在 `setting_definitions.py` 的 `SETTING_GROUPS`，导入期校验「定义用到的 group 必须已登记」且「label 一致」，不一致直接启动失败。

## 五、第三方集成

| 能力 | 当前实现 | 无配置时行为 | 开源版计划 |
|------|---------|-------------|-----------|
| 文件存储 | **local（默认，写卷）** / 腾讯云 COS | local 无需配置；cos 未配置时上传报明确错误 | 已抽象 `services/storage/`：local / cos，新增 s3 · oss 只需加一个文件 |
| 邮件 | SMTP（aiosmtplib） | 验证码发送失败提示 | 追加 `console` 模式（打日志） |
| 短信 | 腾讯云 / 阿里云 | 登录方式不可用 | 追加 `mock` 模式 |
| AI 文本 | DeepSeek / OpenAI / Qwen / 自定义 | 功能入口隐藏或明确报错 | 追加 `mock` 供应商 |
| AI 图片 | DashScope | 同上 | 同上 |
| 图库 | Pexels / Pixabay / Giphy / 百度 / 搜狗 / 多图 / Emoji 等 | 对应源隐藏 | 保留 |
| 支付 | 微信支付 / 支付宝 / 模拟支付 | 支付关闭 | 默认 `mock` |
| 收录推送 | 百度推送 / IndexNow | 跳过并记日志 | 保留 |
| 错误监控 | Sentry | 不加载 | 保留 |
| 统计 | Umami（外链） | 不显示入口 | 移出开源范围 |

**原则**：任何三方能力未配置时，系统必须能启动、能登录、能管内容，影响面收敛到「该功能不可用 + 体检页标红」。

## 六、数据与缓存

### 6.1 数据规模

- 37 张表，按域划分：身份与权限（7）、内容（5）、分类（2）、运营（6）、行为（7）、商业化（4）、系统（5）、待下线（1）；
- 79 个 Alembic 版本；CI 校验 `upgrade → downgrade base → upgrade` 往返。

### 6.2 缓存

| 键 | 内容 | TTL | 失效 |
|----|------|-----|------|
| `content:*` | 内容详情/列表（`content_cache.py`） | 短 TTL | 写操作显式 purge（`content_purge.py`） |
| 菜单/权限 | 前端 sessionStorage 缓存 + 版本号 | — | `MENU_CACHE_VERSION` 递增 |
| 限流计数 | `rate:*` | 窗口长度 | 自然过期 |
| 调度心跳 | `ops:jobs:applied` | 短 | 每轮对齐刷新 |
| 系统状态 | `SYSTEM_STATUS_CACHE_SECONDS` | 可配 | 定时刷新 |

**降级策略**：Redis 不可用时，读路径回退数据库，写路径对敏感端点 fail-closed，并记 `redis_degraded` 日志。
