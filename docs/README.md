## 三、文档维护约定

### 3.1 单一事实来源

⚠️ **清单类信息只在指定位置维护**，其他文档**只引用不复制**（可以写「以 X 为准」，但不要重抄一份数字）：

| 信息类型 | 唯一维护位置 |
|---------|------------|
| 模块数、表数、路由数、页面数、测试用例数、代码行数 | [项目说明](03-开发/项目说明.md) 第三章 |
| **线上运行状态**（内容量 / 健康检查 / SEO 端点实测） | [项目说明](03-开发/项目说明.md) § 1.4 |
| 数据库表结构与字段 | [项目说明](03-开发/项目说明.md) 第四章 |
| 技术选型的依据与取舍 | [技术架构](02-架构/技术架构.md) |
| 部署与运维操作步骤 | [部署说明书](04-运维/部署说明书.md) |
| 关键词体系与内容策略 | [SEO 与 GEO 方案](01-产品/SEO与GEO方案.md) |

### 3.2 文档只描述现状

每个文档陈述**当前实现状态与运维事实**，不保留版本变更记录、「先前 / 现在」的对照叙述、
审查历史与编号引用。历史结论与待办事项不属于正式文档的职责范围。

### 3.3 数字一致性由脚本保证

改完代码后跑仓库根下三个零依赖自检脚本，不要在文档里手工同步数字：

```bash
python scripts/check_docs_links.py        # 文档内链接与锚点是否有效
python scripts/check_env_consistency.py   # compose / .env / Settings 三方环境变量一致
python scripts/check_ci_config.py         # CI 版本 pin 与 Dockerfile 是否一致
```
