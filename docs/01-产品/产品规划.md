# AI学习猫 — 产品规划


---

## 〇、产品定位（2026-10-18 校准）

> **一句话**：AI学习猫是一个**覆盖全领域的结构化教程学习平台**，不是一个工具说明书站。

| 项 | 内容 |
|---|---|
| **是什么** | 以「多章节结构化课程」为核心，配以在线工具、知识百科、资源聚合、扩展推荐的学习平台 |
| **面向谁** | 有自学需求的技术从业者、独立开发者、AI 应用实践者、职场提效人群 |
| **覆盖范围** | **不限领域** —— 人工智能、编程开发、项目实战、设计创作、软件工具、效率办公、产品运营（见第二章 7 大类） |
| **形态边界** | 知识必须能以「课程 / 工具 / 百科 / 资源 / 扩展」五种形态之一承载 |
| **不做什么** | 不做单一工具的说明书站、不做新闻资讯站、不做社区论坛 |

### 为什么早期内容集中在 ComfyUI / Stable Diffusion / Coze

这是**内容冷启动的取舍，不是产品定位**：

1. 新站需要**低竞争、高意图**的词先建立收录与排名。通用词（「Python 教程」「Excel 教程」）的竞争度是垂直长尾词的数十倍，新站正面打不动；
2. 这三个生态在 2025-2026 处于上升期，中文原创供给不足，长尾词密集且便宜；
3. 它们**结构化程度高**（节点有输入/输出参数、扩展有安装指引），最适合先把「百科 + 扩展」两类结构化内容形态跑通、把导入工具验证完。

### 定位边界的四条硬约束

1. 内容库当前以这三个生态为主，是**存量事实**，**不是准入限制**；
2. 后续新增内容**不要求**与 AI 工具链相关 —— 编程、设计、办公、产品等 7 大类同等开放；
3. 五个栏目**领域无关**：任何领域的知识都能落进这五个容器。`nodes` 的 `inputs` / `outputs` / `params` 是通用结构化字段，VS Code 配置项、Figma 快捷键、Excel 函数同样适用；
4. **只有当某类内容无法用这五种形态承载时**（例如实时答疑、视频课程、付费社群），才需要讨论是否新增模块 —— 而不是因为「领域变了」就新增模块。

> ⚠️ 本文件其余章节中出现的 ComfyUI / Stable Diffusion / Coze，除非明确写「定位」，否则一律理解为**当前存量内容与切入品类**。

## 二、教程模块

### 2.1 定位

核心付费内容。内容形态为**多章节结构化课程**，支持三级阅读权限（免费 / 会员 / 积分购买），章节拥有独立 URL（`/tutorials/:id/c/:nid`），是长尾 SEO 的主要承载。

> **首发品类**，也是当前内容储备最集中的方向。它与站点定位**不构成绑定**——平台覆盖全领域（见[第〇章](#〇产品定位2026-10-18-校准)），AI 只是冷启动阶段投入产出比最高的一条线，也是 SEO 方案中 T2 核心词与 T3 长尾词的集中来源。

#### ② 编程开发

前端开发 · 后端开发 · 全栈开发 · Java · Python · JavaScript · React · Vue · Node.js · 数据库 · API · Docker

#### ③ 项目实战

AI项目 · Web项目 · 前端项目 · 后端项目 · 全栈项目 · 开源项目 · 独立开发

> 差异化价值最高的板块：**成品级项目拆解**比零散知识点更难被免费内容替代。

#### ④ 设计创作

UI设计 · UX设计 · 网页设计 · Figma · Photoshop · 视觉设计

#### ⑤ 软件工具

VS Code · Git · GitHub · Postman · Docker · Figma · 开发工具 · 效率软件

#### ⑥ 效率办公

Excel · Word · PPT · Markdown · 自动化 · 知识管理 · 办公技巧

#### ⑦ 产品运营

产品设计 · 产品经理 · SEO · 网站运营 · 内容运营 · 独立站

> ⚠️ **优先级提示**：7 大类中，**① 人工智能**与 ③ 项目实战应优先供给——它们同时满足「搜索需求大」与「付费意愿强」两个条件。其余 5 类（设计/工具/办公/运营/编程基础）建议在 AI 与项目实战建立起稳定流量后再**按搜索数据逐步补齐**，而不是一开始就平均铺开；但它们属于**同一平台的内容**，不是「不做」。

## 三、百科模块

### 3.1 定位

与教程模块结构相近，但**内容深度更浅**——不做完整课程，只做「单点参数查阅」。

当前实现为 **ComfyUI 节点百科**（**存量内容，非定位边界**）：每个节点记录名称、分类、描述、输入参数、输出参数、参数详解、使用示例。

> 数据模型与领域无关：`Node` 的 `inputs` / `outputs` / `params` 是通用「结构化条目」字段，任何具备参数体系的条目都能复用——VS Code 配置项、Figma 快捷键、Excel 函数、Docker 参数皆可。因此「百科」不是「ComfyUI 百科」，只是**现在装的是 ComfyUI 的条目**。

### 3.2 分类体系

采样器 · 加载器 · 条件 · 图像 · 潜空间 · 工具

> **SEO 价值**：节点页是 T5 资源下载词（"ComfyUI 节点大全"、"ComfyUI 自定义节点"）的承载页。⚠️ 但需注意：若内容大量同步自 GitHub README，存在被判低质采集的风险，**必须补充中文原创摘要、适用场景、关联教程链接**（详见 [SEO 方案 2.3 节](../01-产品/SEO与GEO方案.md)）。

### 6.3 与既有模块的关系

**模块本身已落地**（`plugins` 表 + 列表/详情页 + 后台 CRUD + 第三方正文导入），
但下面 6.2 规划的 7 大类 50+ 子类**尚未铺内容**——这属于**内容运营动作**，不是开发缺口。

**与既有模块的关系**：`plugins` 模块（分类 `ComfyUI 节点` / `Coze 扩展` / `其他扩展`）在概念上
**已经覆盖了扩展模块**——例如 ⑥ 中的「ComfyUI 工作流节点」与 ① 中的「Coze 相关」。
因此 6.2 的分类体系**不再作为独立模块实现，而是作为 `plugins` 的分类维度按需扩充**。

结论：并入 `plugins` 模块（分类维度按需扩充），不新建 `extensions` 表与路由。

> **为什么选 A**：扩展模块与「插件推荐」在用户认知上是同一件事（都是「给某个工具装个增强件」），
> 独立建模块会让用户困惑「我该去哪个栏目找」。作为 `plugins` 的分类维度扩充，成本最低且体验更一致。
>
> **落地方式**：需要新增分类时，在后台「分类管理」里给 `plugin` 模块加分类即可（**运营动作，无需开发**）。

| 富文本编辑器 | 自定义 blot、callout、附件、响应式视频、代码块高亮、表格、快捷键体系 |
| 数据看板 | 手写 SVG 图表（零图表库依赖） |
| 访问统计 | Umami 自托管 |
| AI 翻译 | 异步任务式内容翻译 |
