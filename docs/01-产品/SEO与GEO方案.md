## 0. 现状诊断（**历史快照，2026-08 方案出发点，已过时**）

> ⚠️ 以下为方案初版（2026-08）的现状判断，**多数问题现已解决**，仅作方案推演的背景保留。**当前状态一律以 0.5 节为准。**

| 维度 | 现状 | 影响 |
|------|------|------|
| 渲染架构 | React SPA 纯客户端渲染，所有内容依赖 JS 执行后才出现 | **致命**：百度爬虫基本抓不到正文（2026 年仍是百度收录第一杀手），Google 可渲染但收录延迟数天 |
| TDK | 仅 `frontend/index.html` 一份静态 title/description；全站仅 `Search.tsx` 动态改过 title | **严重**：几百个内容页共用一个标题，搜索引擎无法区分页面价值 |
| robots.txt / sitemap.xml | 均不存在 | **严重**：收录入口缺失 |
| URL 规范化 | `nginx.conf` 同时接受 `wdmao.cn` 与 `www.wdmao.cn`，无 301；路径为纯数字 ID（`/tutorials/3`） | 中：权重分散、URL 无关键词信号 |
| 404 处理 | `try_files ... /index.html` 兜底，任意错误 URL 均返回 200 | 中：产生大量重复内容，拉低整站质量分 |
| 性能基础 | 已有 gzip、静态资源 30d immutable 缓存、首页 LCP 预加载（`fetchpriority="high"`）、路由级 lazy loading | 良好，处于中上水平 |
| 内容生态 | 教程/插件/节点/资源/工具五大栏目，部分插件内容同步自 GitHub README | 机遇与风险并存：同步内容若无中文增值，易被判低质采集页 |

**结论**：本站不是"内容不好"，而是"内容对搜索引擎不可见"。方案的优先级必须是 **技术可达性 → 页面元信息 → 内容 → 外链 → GEO**，顺序不可颠倒。

- 每季度迭代一次：T3 词中排名 11-20 的页面优先加强（内链+内容扩充），这是 ROI 最高的动作。

## 2. 网站内容优化策略

### 2.1 首页

- **Title**：`全领域教程_在线工具_知识百科_资源下载 - AI学习猫`（覆盖平台定位，品牌后置；**此值已于 2026-10-18 落到 `frontend/index.html` 与 `Home.tsx` 两处，须保持一致**）。
  ⚠️ **不要把首页 Title 收窄成单一工具名**——首页是「全领域教程平台」的唯一承载页，Title 写成 `ComfyUI 教程 _ SD 实战` 会让整站定位与内容范围脱节，后续铺编程/设计/办公内容时首页失去承接能力。垂直流量交给 `/tutorials` 与分类页去承接；
- **Description**：自然植入平台主干词——"教程""在线工具""知识百科""资源下载"，并按当期主推品类补 1-2 个垂直词（如"AI 绘画教程"），控制在 80-110 汉字（搜索结果摘要不截断）；
- **H1 唯一化**：首屏主标题作为全站唯一 H1（当前视觉主文案应落成语义化 `<h1>` 而非纯样式标签）；
- 首屏下方的"热门学习方向"已动态化（读取后台分类），确保分类名即关键词（后台建分类时就按搜索词命名）；
- 增加 JSON-LD `Organization` + `WebSite`（含 SearchAction 站内搜索语法）。

### 2.2 栏目列表页（tutorials / plugins / nodes / resources / tools）

- 每页独立 TDK 模板，如：`扩展下载 _ 插件大全 - AI学习猫`（垂直品类再细分一层，如 `ComfyUI 插件下载 _ 节点大全`）；
- 页面顶部增加 150-300 字的**栏目导语**（含核心词的自然语言描述）——这是列表页唯一可被索引的原创正文，当前列表页近乎零文本；
- 筛选项输出为可抓取的 `<a>` 链接（分类筛选页如"扩展 > 图片处理""教程 > 前端开发"可成为优质长尾落地页）。

### 2.3 详情页（最重要的 SEO 资产）

| 页面 | Title 模板 | 结构化数据 |
|------|-----------|-----------|
| 教程详情 | `{教程名} - {领域}实战教程 _ AI学习猫` | `Course` + `BreadcrumbList` |
| 章节页 `/tutorials/:id/c/:nid` | `{章节名} _ {教程名} - AI学习猫` | `Article` |
| 插件/节点 | `{名称}：{一句话功能} _ {宿主平台}扩展详解` | `SoftwareApplication` |
| 资源 | `{资源名}下载 _ {类型} - AI学习猫` | `Product`（免费） |
| 工具 | `{工具名} - 免费{功能}在线工具 _ AI学习猫` | `WebApplication` + `FAQPage` |

关键动作：

1. **章节页是长尾金矿**：每个章节天然对应一个具体问题（如"LoRA 模型接入"），当前章节 URL 已独立（`/tutorials/:id/c/:nid`），为每章配独立 TDK + 面包屑即可批量产出长尾落地页；
2. **插件/节点页反采集改造**：GitHub README 同步内容外，强制增加三段原创模块——中文功能摘要（80 字+）、适用场景说明、关联本站教程链接。既规避"相似度超 70% 判采集"风险，又形成站内内链；
3. **内链体系**：教程详情页已有"相关推荐"，再补两个自动规则——章节正文中的术语自动链接到对应"节点/插件"详情页；插件页反向链接到使用它的教程；
4. **图片 alt**：所有封面图 alt 使用"内容描述+关键词"，禁止空 alt。

### 2.4 承接问题型搜索

问题型搜索由 `nodes`（知识百科）的 `faq` / `troubleshooting` 分类承载，**不新建 `/blog` 或 `/wiki` 栏目**。

理由：`nodes` 本身就是知识库——有分类、有正文、已进 sitemap 与预渲染白名单、已有全文检索。
再建一个栏目会让同一批问题词被两个栏目争抢，分裂 SEO 权重与用户认知。

落地方式：在后台「分类管理」中给 `nodes` 增加一条分类即可，属运营动作，无需开发。

现有教程偏课程化（长、结构深），缺少承接**问题型搜索**的短内容。用 `nodes` 的 `faq` 分类承载：

- 每篇 800-1500 字，一篇文章只回答一个问题（切入品类如"ComfyUI 报错 xxx 怎么办"，全领域如"Python 虚拟环境怎么配""Git 冲突怎么解"）；
- 生产节奏：每周 2-3 篇，题材直接来自 1.2 节词库中 T3/T4 词；
- 每篇文章文末 CTA 引流到对应教程/工具，形成"搜索流量 → 博客 → 教程 → 注册"的转化链。

## 3. 技术SEO优化要点

### 3.1 首要任务：让爬虫看到内容（动态渲染方案）

SPA 改 SSR（Next.js）是长期理想方案但改造成本过高，**推荐中期方案：动态渲染**——用户照常用 SPA，爬虫请求由 Nginx 按 User-Agent 分流到预渲染服务：

```nginx
# nginx.conf location / 中追加
location / {
    if ($http_user_agent ~* "Baiduspider|bingbot|Googlebot|YandexBot|Sogou|360Spider|Bytespider") {
        proxy_pass http://prerender:3000;
        break;
    }
    root /usr/share/nginx/html;
    try_files $uri $uri/ /index.html;
}
```

配套建议（贴合现有技术栈）：

- 预渲染服务自建 Docker 容器（rendertron 或 Node+Puppeteer，社区成熟方案），**结果缓存进现有 Redis**（TTL 24h，内容更新时主动失效）——避免每次爬虫请求都启浏览器，这是该方案的性能命门；
- 爬虫访问不存在的资源时由渲染服务探测 API 返回**真正的 404**，修复当前"全站 200"问题；
- 该方案对 Google 是官方认可的过渡方案，对百度正是其推荐的处理 JS 站的方式。

### 3.2 页面级 TDK 系统

- 引入 `react-helmet-async`，封装 `useSEO({ title, description, canonical, jsonLd })` Hook，五个详情页类型 + 六个列表页全部接入；
- 每个 SEO 页面输出 `<link rel="canonical">`，统一为 `https://www.wdmao.cn/...`。

### 3.3 URL 结构

- **www 收敛**：裸域 301 到 `www.wdmao.cn`（当前两者并存，权重分散）；
- **slug 化（第二阶段做）**：为教程/插件等增加 `slug` 字段，URL 从 `/tutorials/3` 变为 `/tutorials/python-venv-setup`，旧 URL 301 跳转；改动量大，放在收录稳定后执行；
- 全站 HTTPS 确认：EdgeOne 边缘已具备 HTTPS，确保 canonical、sitemap、内链统一 https。

### 3.4 robots.txt（可直接上线）

```text
User-agent: *
Disallow: /admin/
Disallow: /profile/
Disallow: /auth
Disallow: /login
Disallow: /search
Disallow: /*?page=  ; 分页参数页不索引
Sitemap: https://www.wdmao.cn/sitemap.xml
```

**sitemap.xml 用后端生成**（内容在数据库里，前端构建时拿不到）：

- FastAPI 增加 `GET /sitemap.xml` 路由：遍历已发布 tutorials（含章节）、plugins、nodes、resources、tools，输出 `<loc>` + `<lastmod>`（用 `updated_at`）+ `<changefreq>`；
- 章节页数量会随教程增长，注意百度单文件上限 5 万 URL / 50MB，超限拆 sitemap-index；
- 发布/更新内容时自动触发百度 API 推送（`data.zz.baidu.com/urls?site=...&token=...`，POST 正文每行一个 URL），发布钩子里做成"失败不影响发布"的异步任务。

### 3.5 移动适配

- 已是响应式（viewport 正确、有移动导航），保持 URL 统一（不做 m. 独立站）；
- 百度已是移动优先索引，用手机实机抽查五个详情页的首屏体验（字体、表格横向滚动、图片宽度）；
- 在百度资源平台开启"站点属性-适配声明"。

### 3.6 加载速度（Core Web Vitals）

目标（移动端 P75）：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1。已有基础好，剩余动作：

1. **antd 体积是最大嫌疑**：首屏 bundle 审查，antd 全量引入改为按需/替换为轻量组件（这是 React+antd 站点最常见的 LCP 瓶颈）；
2. EdgeOne 开启 Brotli 压缩与图片 WebP 自适应转换（站内自己就有图片压缩工具，封面图先批量压一遍）；
3. 列表页图片全部 lazy-load + 固定宽高比（防 CLS）；
4. 章节正文 RichText 内图片延迟加载。

### 3.7 结构化数据（JSON-LD）

按 2.3 节表格逐页型接入；全站另加 `BreadcrumbList`（首页 > 教程 > 某教程 > 某章节）与 `FAQPage`（工具页放 3-5 条真实 FAQ，有机会获得百度/Google 富摘要）。

## 4. GEO 定位优化具体措施

先给出一个诚实的判断作为策略前提：**本站是在线平台而非本地商家，传统"城市+服务"本地词（如"北京 AI 培训"）的搜索意图指向线下机构，与本站业务错配，ROI 低**。因此 GEO 策略重心放在**品牌地理资产保护**与**华语市场分层渗透**上，本地商家动作做"低投入、保底型"配置。

### 4.1 市场分层

| 市场 | 主搜索引擎 | 动作 |
|------|-----------|------|
| 中国大陆（主战场） | 百度 + 微信搜一搜 + 知乎/小红书站内搜索 | 全部资源投入 1-3 节方案 |
| 中国港澳台地区 · 新加坡 / 马来西亚 · 海外华人 | Google | 繁体关键词版本（教學/課程/軟體），详情页 description 兼顾繁体词；Google 抓取经由 EdgeOne 海外节点，可达性无虞 |
| 全球英文用户 | 暂不投入 | 与现有内容语言不匹配，列为远期 |

### 4.2 本地商家信息（保底型配置）

- **百度地图商户标注**：若有营业执照（个人主体也可标注公司/工作室），在百度地图商户中心完成"AI学习猫"认证。作用不是引流而是**品牌词搜索时占据地图卡片、增强实体可信度**——这对新站的可信度加权是实打实的；成本一次半天，优先级中；
- **Google Business Profile**：仅当有实际办公地址再做；纯线上业务强行创建反而有封禁风险，跳过；
- 确保网站页脚展示 ICP 备案号并链接至工信部备案系统（.cn 域名+国内服务器的合规底线，也是百度信任信号）。

### 4.3 Citations 建设（中文版 NAP 一致性）

中文生态没有 Yelp 式 citations 体系，等价物是**全平台品牌信息一致性**——"AI学习猫 / wdmao.cn / 一句话简介 / logo"四要素在以下平台完全一致：

1. 知乎机构号/专栏、微信公众号（搜一搜可被索引）、CSDN/掘金账号简介；
2. 主流网站目录/导航站（中文导航站提交收录）；
3. 百度百科词条（创建"AI学习猫"品牌词条，难度中等但品牌搜索结果一劳永逸）。

### 4.4 地域化/语言化内容创作

- **年份时效词**：中文搜索"教程+年份"是稳定模式（"Python 2026 教程""ComfyUI 2026 教程"），每年 1 月批量更新教程页 TDK 与首段的年份标注，成本极低；
- **繁体词覆盖**：仅在 description 与正文自然提及（如"繁體版課程內容同步更新"），不必做整站翻译；
- **城市词**：仅当未来开展线下活动/城市社群时才建地域页面，当前明确不做（避免低质薄页）；
- 百度统计的**地域分布报告**每季度复盘一次，若某省流量异常高，再定向产出内容（数据驱动而非拍脑袋建地域页）。

### 4.5 2026 增量视角：GEO 的另一重含义（Generative Engine Optimization）

必须提醒：2026 年"GEO"更多指**生成式引擎优化**——被豆包、Kimi、ChatGPT、文心一言等 AI 搜索引用。您的目标用户恰是重 AI 工具用户，大量问题会在 AI 助手里问。三条低成本动作：

1. 章节正文使用"问题-结论先行-步骤"结构（AI 引擎偏爱的可引用格式），首段 100 字内给出直接答案；
2. ✅ **已落地且超出方案**：robots.txt 含 **14 个具名 AI/LLM 爬虫全站放行段**；nginx 的 `map $http_user_agent` 把其中 **11 个 AI 爬虫**（GPTBot / OAI-SearchBot / ChatGPT-User / ClaudeBot / Claude-User / Claude-SearchBot / PerplexityBot / Perplexity-User / Amazonbot / Applebot / meta-externalagent）进一步**分流到预渲染**（AI 爬虫不执行 JS，必须预渲染才能抓到正文）；另有 `/llms.txt` 动态生成（GEO 面向 AI 引擎的站点说明）。技术上本条已从「建议」变为「已上线」。
3. 知乎/CSDN 分发内容（见第 5 节）本身就会被 AI 引擎收录，是进入 AI 答案的最短路径。

## 8. 风险与注意事项

1. **沙盒期心理预期**：新站/低权重站百度有 1-3 个月考核期，前两个月数据平淡是正常曲线，不要因短期无收录推翻方案；
2. **动态渲染成本**：Puppeteer 服务内存占用高，务必先有缓存层再放量，否则爬虫高峰会打爆容器（建议独立容器+内存限制）；
3. **转载反噬**：分发到 CSDN/知乎的内容若全文无出处声明，可能反过来判定本站为采集方——发布 SOP 里固化"首发本站、转载带原文链接"；
4. **内容相似度**：插件/节点页 GitHub 同步内容占比过高是最大批量降权风险点，2.3 节的反采集改造优先级要守住。

### 10.7 维护规则

1. **查词在前**：每次新建教程/工具/资源前先查本表，标题按目标词设计；
2. **一页一主词**：每个详情页只锁定 1 个主词，主词进 title 前半段与 H1；
3. **季度迭代**：排名 11-20 的页面优先加强（内链 + 内容扩充），ROI 最高；
4. **数据回填**：百度资源平台接入满 1 个月后，把"曝光未点击"词回填本表并优先改 TDK。
