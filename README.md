# AI 学习猫 · 后台管理端

**一个自带按钮级 RBAC、全量操作审计、UGC 审核与 AI 写作的内容中台。**
用它管内容与用户，用它的 API 渲染你自己的站点。

> 中文文档（[English](README.en.md)）

> **定位说明**：这不是又一个 CRUD 脚手架，也不是低代码平台。
> 它解决的是一个具体问题——**多人协作运营一个内容站时，权限要细、动作要留痕、内容要好写**。

## 为什么不是另一个后台模板

| 常见痛点 | 本项目的做法 |
|---------|------------|
| 菜单有入口，点进去 403 | 权限码**单一声明**，派生菜单/路由/接口/按钮四处，物理上不可能不一致 |
| 新接口忘了加权限判断就裸奔 | 路由规则表 **fail-closed**：未登记的请求一律 403 |
| 出了事查不到是谁改的 | 写操作**强制留痕**，漏写审计会让测试变红 |
| 多人用同一套账号，权责不清 | 63 个权限码、3 个内置角色，可自定义到按钮级 |
| 第三方密钥明文躺在数据库里 | 密钥 **Fernet 加密落库**，后台只回显掩码，误提交掩码不会覆盖真值 |
| 编辑器是哑的，配图靠手找 | 内置 Quill 富文本 + AI 改写/续写/插图 + 图库检索 |

## 快速开始

```bash
git clone <repo-url> && cd <repo>
cp .env.example .env          # 只需填 SECRET_KEY / 数据库密码
docker compose up -d
```

打开 `http://localhost/admin`，首次访问进入**安装向导**：创建管理员 → 选择存储方式 → 完成。
**不需要手动改一堆环境变量，也不需要配任何第三方 Key。**

> 本地开发（不用 Docker）见[开发文档 §二](docs/07-开源文档/05-开发文档.md)。

**默认账号**：安装向导中自行设置。未使用向导时由 `ADMIN_PASSWORD` 决定，未设置则随机生成并在启动日志中打印一次。

### 想先看看有数据的样子？

```bash
docker compose exec app python seed_demo.py
```

会灌入 5 篇教程（含 15 个章节）、示例分类、用户、评论、反馈、公告与积分流水，
并**现场生成封面图与头像**写入存储——所以图片是真能显示的，不是 404 占位。

脚本是幂等的（标题带 `【示例】` 前缀），重复执行会跳过；库里已有真实内容时必须加 `--yes` 才继续。

### 用内容 API 渲染你自己的站点

后台管内容，前台自己写。内容接口有独立的命名空间与独立文档：

- 接口文档：`http://localhost/api/v1/content/docs`
- 机器可读：`http://localhost/api/v1/content/openapi.json`

```bash
# 首页聚合：一屏所需的教程、分类、公告一次拿齐
curl -s http://localhost/api/v1/content | jq '.data.tutorials[:3]'

# 教程列表（分页）
curl -s 'http://localhost/api/v1/content/tutorials?page=1&page_size=10' | jq '.data.items'

# 章节树 → 正文
curl -s http://localhost/api/v1/content/tutorials/4675248031/nodes | jq '.data'
curl -s http://localhost/api/v1/content/tutorials/4675248031/nodes/123 | jq '.data.content'
```

**匿名可读**：首页聚合、教程列表、试读（`.../intro`，已含章节树）、分类、公告。
**需要用户 token**：教程详情与章节正文——免费教程登录即读，会员教程需 VIP 或已购买。
付费解锁与分类增删改**不在**这个命名空间里——它们分别是交易与后台操作。

一个能直接跑的样板（含匿名与登录两种视角）：[`examples/frontend-minimal`](examples/frontend-minimal/)。

> 旧的 `/api/v1/{tutorials,categories,home,announcements}` 仍然可用（OpenAPI 里标了 `deprecated`），
> 保留是为了不打断已有的用户端；新项目请直接用 `/api/v1/content/*`。

## 功能

| 模块 | 能力 |
|------|------|
| **内容（示例模块）** | 教程（多级章节树）/ 分类 / 素材库 —— 教程是**可照抄的样板**：列表、树形章节、编辑器、审核、回收站全套 |
| **编辑** | Quill 2 富文本（表格、代码块、图注、目录、Markdown 粘贴）、AI 改写续写插图、图库检索插入、草稿预览 |
| **审核** | 机审留痕复核、用户举报处理、评论治理（可删可恢复，不可编辑） |
| **用户** | 用户 CRUD、禁用、软删与恢复、积分调整、角色分配、实名审核 |
| **权限** | 角色 / 权限树 / 部门 / 岗位目录，63 个权限码，按钮级 |
| **审计** | 全量写操作留痕；高危操作记录**字段级 diff**（旧值 → 新值，敏感值掩码、长值截断），按模块 / 操作人 / 时间 / 结果检索 |
| **体验** | 全局命令面板（Ctrl/Cmd + K）：跳页面、搜用户 / 教程、切主题 / 布局；搜索直接落到筛选后的列表或编辑页。≤767px 自动改用抽屉菜单，评论 / 审核 / 反馈页优先展示内容列，工具条与页头纵向铺满 |
| **数据分析（演示）** | 独立「数据分析」页：KPI 趋势 / 阅读趋势 / 流量来源 / 内容排行 / 内容四象限 / 新老用户 / 活跃时段 / 转化漏斗 / 质量雷达 / 搜索热词；图表由 **ECharts** 渲染，带 hover tooltip / emphasis、数字滚动、折线从基线拉起、柱状/环形/雷达展开等动效，切范围/换一批会重播；**全部为浏览器本地假数据**，用于接入真实指标前的布局与交互参考 |
| **菜单管理** | 侧边栏菜单的中/英名称、图标、顺序与可见性，保存即生效并写审计；路由与权限码仍由代码同源定义，页面不提供新建/删除，避免 404 / 403 死入口 |
| **字典管理** | 字典类型 + 字典项两栏管理：编码/名称/说明、标签/值/排序/默认项/启用状态；默认项唯一、删除类型前校验字典项；内置内容/机审/反馈/用户四组常用字典；写操作全审计 |
| **监控管理** | 在线用户（全站会话、设备/IP/活跃时间、强制下线）、服务器监控（CPU/内存/磁盘/Swap/进程）、缓存监控（Redis INFO、键空间前缀分布、命中率）；全部只读，Redis/psutil 故障时降级为「不可用」 |
| **运营** | 公告（定时上下线）、系统通知、充值套餐与订单（只读）、搜索词分析 |
| **系统** | 26 组 138 项配置、登录方式、管理员强制二次验证、支付渠道、邮件、AI 模型与单价、定时任务、法律文档、**部署体检**、列表导出、**顶栏待办中心**、**统一回收站**、**版本与升级**、**备份管理** |
| **AI** | 多供应商（OpenAI 兼容 / DeepSeek / Qwen）、单模型单价、全站成本护栏、单用户配额 |

> 完整清单见[功能文档](docs/07-开源文档/01-功能文档.md)，含明确不支持的边界。

## 工程能力

开源项目最该被审视的是工程纪律，不是功能数量。

| 能力 | 本项目 | 同类开源后台常见情况 |
|------|--------|-------------------|
| 后端测试 | **155 个文件 / 1840 个用例**，全程离线可跑（不需 MySQL/Redis） | 0 ～ 数十 |
| 架构守卫 | 权限覆盖 / 审计覆盖 / 菜单一致性 / 任务注册表，均有用例守着 | 少见 |
| 密钥存储 | Fernet 加密落库 + 掩码哨兵 | 明文存表或存配置文件 |
| 审计 | 写操作强制留痕，缺失即测试失败 | 有日志但无覆盖保障 |
| 限流 | 敏感端点 Redis 故障时 **fail-closed** | 有，但故障即放行 |
| 权限 | 权限码 / 菜单 / 路由 / 守卫**同源** | 多处手工对齐，易漂移 |
| 迁移 | 79 个版本，CI 校验 upgrade → downgrade → upgrade 往返 | 常有 `create_all` 混用 |

## 已知限制

开源项目说清边界比堆功能更可信：

- 仅支持 **MySQL 8**（依赖 `ngram` 中文全文索引）
- **单实例部署**：定时调度在进程内，横向扩展需自行拆分
- 后台**外壳、登录页、命令面板与列表通用组件**已支持中 / 英切换（选择持久化，英文菜单由后端按 `Accept-Language` 下发）；教程 / 用户 / 运营等业务页面文案仍为简体中文
- 无多租户、无低代码表单引擎、无站内资金操作（退款走商户后台）

## 贡献

欢迎 Issue 与 PR。开始前请读 [CONTRIBUTING.md](CONTRIBUTING.md)，特别注意三条硬约定：

1. 新增写操作**必须**写审计，否则 CI 红；
2. 新增管理端接口**必须**在路由规则表登记，否则 403；
3. 新增权限码**必须**同步菜单项，否则测试失败。

`good first issue` 标签下是适合入门的任务。
安全问题请走 [SECURITY.md](SECURITY.md) 的私密通道，不要开公开 Issue；版本变更见 [CHANGELOG.md](CHANGELOG.md)。
